# 旧版 cmr-backend / cmr-web 全量迁移计划

目标：把旧工程 `cmr-backend`（173 个 Java 文件、11 个业务域、约 100 个接口）与
`cmr-web`（8 个路由页、约 4k 行视图、3 个 API 文件）完整迁入 `hsmty-cmr`
的 `client → core → start` 架构与 qiankun 子应用，功能对齐旧版联调结果。

## 1. 迁移原则

| 项 | 旧版 | 新版做法 |
| --- | --- | --- |
| 包名 | `com.hsmty.cmr.*` | 保持不变，直接落在 core 的 `com.hsmty.cmr` 下 |
| 接口路径 | `/hs-api/cmr/**` | 保持不变 |
| 返回信封 | `{code:0,msg,data}` | 改为平台 `ApiResult{code:"0000",message,data,param}`，前端 http 层统一适配 |
| 鉴权 | JWT + `cmr_user` 表 + 登录页 | 去掉登录/JWT，身份与权限码取自平台 UAP（本机 `local` profile 注入固定身份）；保留 `GET /cmr/auth/me` 返回当前用户权限 |
| 字典 | `cmr_dict` + `/dict(s)/{type}` | 先按旧表迁移，后续再评估切平台 `sys_dict`（登记偏差） |
| 审计字段 | `BaseEntity` + `AuditListener` | 暂保留旧实现，避免大面积改实体；后续统一到 `EntityChangeListener`（登记偏差） |
| 雪花 ID | `SnowflakeIdWorker` | 保留旧实现（与平台 `SzIdGenerator` 并存） |
| 算子调用 | `RestClient` + Jackson 2 `JsonNode` | 改为 Feign + Jackson 3（`tools.jackson`），或保留 `RestClient` 但换 JSON 库；统一在 core 内封装 |
| 数据库 | 旧 Liquibase 001–013 | 直接迁入新 core，作为 `cmr` 业务表的唯一事实源；删除此前新建的 002–004（表结构以旧版为准） |
| 文件 | 共享卷逻辑路径 + `/file` 预览/打包/上传 | 按旧版迁移；此前模板的 `cmr_file_object` 保留但不作为检索主链路 |

## 3. 分期

### 阶段 0：地基（本次开始）

1. Liquibase 旧版 001–013 迁入 `core/resources/db/changelog/cmr/`，替换旧 002–004。
2. 迁入旧版 `common`（id、bizNo、基础实体、审计监听、异常转换）与 `CmrProperties`。
3. 迁入 `operator`（9 个算子客户端）与 `file`（共享卷）。
4. 保留平台 `ApiResult` 边界，旧业务代码内部仍可用平台返回类型。

### 阶段 1：建库链（数据集/数据源/索引/任务）

- 迁入 dataset/task 域与 401–406 流水线，打通上传 → 解析 → 评分 → 入库 → 索引 → 校验。

### 阶段 2：检索主链

- 迁入 strategy 域（策略版本、场景生效、模型白名单）。
- 迁入 search 域（407/408、结果回看、重跑、采用/废弃、点击、赞踩、收藏、历史、摘要、行为、屏蔽）。

### 阶段 3：评测与运营

- evaluation（评测集、标注、评测执行、重放）与 operation（反馈、推荐词）。

### 阶段 4：前端全量复刻

- 迁入 PortalLayout 与 8 个视图、3 个 API 文件；http 层改平台信封。
- 路由挂到 `/sdom-hsmty/cms/**`，菜单/权限按平台口径。
- 去掉登录页（UAP 负责），`/auth/me` 提供权限码。

### 阶段 5：库表初始化与验收

- 菜单/字典初始化脚本（需号段）。
- 对照旧版逐页回归：建库链、检索、策略、评测、运营、任务。

## 4. 已知风险

1. Spring Boot 4 + Jackson 3 与旧版 Jackson 2 的 JSON 处理差异，集中在算子客户端与 JSON 字段。
2. 旧版 `TableDef` 需要 `mybatis-flex-processor`，新 core 目前未引入。
3. 旧 `BaseEntity` 审计字段与平台 `EntityChangeListener` 并存，需要避免双重填充。
4. 旧版 `cmr_user`/JWT 移除后，`AuthContext` 的调用点需改为平台安全上下文。
5. 旧表 `cmr_index`/`cmr_search_history`/`cmr_result_item` 与新表结构不同，本地库需要清掉旧表重新执行 Liquibase。
