# 本机联调手册：服务启动与数据库操作

> 适用：`hsmty-cmr` 在本机的端到端联调（Windows + Git Bash）。
> 命令一律单行执行，不要拆分或使用续行符。
> 本机 `local` profile 放行全部路径并注入固定身份，**仅限本机使用，不得用于共享/生产环境**。

---

## 一、前提条件

| 依赖 | 说明 |
| --- | --- |
| Docker Desktop | 提供 MySQL 容器 `cmr-mysql`（`127.0.0.1:3306`，库 `sd_data_engineering`，用户 `cmr`） |
| Redis | Windows 服务 `Redis`，`127.0.0.1:6379` 单机，`local` profile 直连（不走哨兵） |
| JDK 21 | `C:/Dev/jdk-21.0.13+9` |
| Maven 3.9 | `C:/Dev/apache-maven-3.9.11/bin/mvn.cmd`，配合仓库自带 `settings.xml` 与本地仓库 |
| Python | 仓库根 `.venv`，用于启动算子 |
| Node.js | `web/` 下 `npm install` 已完成 |

Docker 守护进程未启动时先开 Docker Desktop：

`powershell -NoProfile -Command "Start-Process 'C:\Program Files\Docker\Docker\Docker Desktop.exe'"`

Redis 未启动时（服务方式安装，通常开机自启）：

`powershell -NoProfile -Command "Start-Service Redis"`

## 二、启动顺序

顺序固定为 **MySQL → 算子 → 后端 → 前端**（后端依赖 MySQL 与 6300 算子，前端只依赖后端）。

### 1. MySQL（`cmr-mysql` 容器）

`docker start cmr-mysql`

健康检查（返回 `mysqld is alive`）：

`docker exec cmr-mysql sh -c 'mysqladmin ping -ucmr -p"$MYSQL_PASSWORD"'`

### 2. 算子（6300），工作目录 `e:\HYQX\跨模态检索`

`.venv/Scripts/python.exe -m uvicorn operators.router.main:app --host 127.0.0.1 --port 6300`

验证：`curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:6300/openapi.json` 返回 `200`。

### 3. 后端（18080，`local` profile），工作目录 `e:\HYQX\跨模态检索\hsmty-cmr`

`LOCAL_DB_PASSWORD=$(docker exec cmr-mysql printenv MYSQL_PASSWORD) "C:/Dev/jdk-21.0.13+9/bin/java.exe" -jar hsmty-module-cmr-start/target/hsmty-module-cmr-start.jar --spring.profiles.active=local`

验证：`curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:18080/hs-api/cmr/dict/types` 返回 `200`。

**改代码后重新打包**（先停掉旧进程，否则 jar 被占用会导致 `Unable to rename ...jar.original`）：

`powershell -NoProfile -Command "Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match 'hsmty-module-cmr-start' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }"`

`JAVA_HOME=C:/Dev/jdk-21.0.13+9 C:/Dev/apache-maven-3.9.11/bin/mvn.cmd -o -s settings.xml -Dmaven.repo.local=C:/Users/23600/.m2/repository -DskipTests -pl hsmty-module-cmr-core,hsmty-module-cmr-start -am package`

> `-o`（离线）模式下不要加 `clean`：`maven-clean-plugin` 来自离线不可用的仓库，会直接失败。
> `local` profile 启动时自动开启 Liquibase，新增的 changeSet 会在启动过程中执行。

### 4. 前端（9849），工作目录 `e:\HYQX\跨模态检索\hsmty-cmr\web`

`npm run dev`

`web/.env.local` 已配置：

```
VITE_PORT=9849
VITE_PROXY_TARGET=http://127.0.0.1:18080
```

## 五、数据库增删改查

### 5.1 连接方式

**非交互执行单条 SQL**（推荐，密码不落入命令历史）：

`docker exec cmr-mysql sh -c 'mysql -ucmr -p"$MYSQL_PASSWORD" --default-character-set=utf8mb4 sd_data_engineering -e "SELECT COUNT(*) FROM cmr_dataset;"'`

**交互式命令行**（连续多条时用）：

`docker exec -it cmr-mysql sh -c 'mysql -ucmr -p"$MYSQL_PASSWORD" --default-character-set=utf8mb4 sd_data_engineering'`

- 密码只存在容器环境变量里，用 `docker exec cmr-mysql printenv MYSQL_PASSWORD` 查看，**不要写进仓库、脚本或文档**。
- 中文内容必须带 `--default-character-set=utf8mb4`，否则会乱码。
- SQL 字符串字面量用双引号（MySQL 默认未开启 `ANSI_QUOTES`）；外层用单引号包住整条 `-e`。

### 5.2 查询

`docker exec cmr-mysql sh -c 'mysql -ucmr -p"$MYSQL_PASSWORD" --default-character-set=utf8mb4 sd_data_engineering -e "SELECT id,biz_no,word,scene,enabled,sort,del_flag FROM cmr_recommend_word ORDER BY sort;"'`

查表结构：`docker exec cmr-mysql sh -c 'mysql -ucmr -p"$MYSQL_PASSWORD" --default-character-set=utf8mb4 sd_data_engineering -e "SHOW COLUMNS FROM cmr_recommend_word;"'`

查全部业务表：`docker exec cmr-mysql sh -c 'mysql -ucmr -p"$MYSQL_PASSWORD" --default-character-set=utf8mb4 sd_data_engineering -e "SHOW TABLES LIKE \"cmr%\";"'`

### 5.3 新增

业务表主键是**雪花 ID（`bigint`，非自增）**，手工插入必须自带唯一 bigint；`biz_no` 一般也是唯一键。

`docker exec cmr-mysql sh -c 'mysql -ucmr -p"$MYSQL_PASSWORD" --default-character-set=utf8mb4 sd_data_engineering -e "INSERT INTO cmr_recommend_word (id,biz_no,word,scene,enabled,sort,del_flag) VALUES (900000000000000001,\"RW9000001\",\"跨模态检索\",\"all\",1,10,\"F\");"'`

### 5.4 修改

`docker exec cmr-mysql sh -c 'mysql -ucmr -p"$MYSQL_PASSWORD" --default-character-set=utf8mb4 sd_data_engineering -e "UPDATE cmr_recommend_word SET word=\"多模态检索\", sort=20, update_time=NOW() WHERE biz_no=\"RW9000001\";"'`

`create_time`/`update_time` 有默认值，`update_id`/`create_id` 由框架的 `EntityChangeListener` 在走接口时填充；手写 SQL 需要时自行补。

### 5.5 删除（逻辑删除）

业务表统一逻辑删除，**不要物理 `DELETE`**：`del_flag` 正常为 `F`、删除为 `T`，查询由框架自动过滤。

`docker exec cmr-mysql sh -c 'mysql -ucmr -p"$MYSQL_PASSWORD" --default-character-set=utf8mb4 sd_data_engineering -e "UPDATE cmr_recommend_word SET del_flag=\"T\", update_time=NOW() WHERE biz_no=\"RW9000001\";"'`

恢复一条被逻辑删除的数据：

`docker exec cmr-mysql sh -c 'mysql -ucmr -p"$MYSQL_PASSWORD" --default-character-set=utf8mb4 sd_data_engineering -e "UPDATE cmr_recommend_word SET del_flag=\"F\" WHERE biz_no=\"RW9000001\";"'`

> 只有需要彻底抹掉测试脏数据时才用 `DELETE`，且只针对自己造的数据。

### 5.6 操作规矩

1. 日常业务数据优先走页面或接口：手工 SQL 容易漏审计字段、绕过唯一键与业务校验，还可能和 Redis 缓存不一致。
2. 平台表 `sys_dict*`、`sys_menu` 等由 `hsmty-common-*` 维护，业务侧不手工增删。
3. 表名一律 `cmr_` 前缀；跨模块改表、改公共表都不允许。

## 六、表结构变更（Liquibase）

改表结构**不直接 ALTER 数据库**，一律新增 Liquibase 脚本，`local` profile 启动时自动执行。

1. 新文件放 `hsmty-module-cmr-core/src/main/resources/db/changelog/cmr/`，序号三位递增（现有 `001`–`022`）。
2. 在 `db/changelog/module-cmr-changelog.xml` 里 `include`，必须带 `relativeToChangelogFile="false"`：

   ```xml
   <include file="db/changelog/cmr/023_cmr_xxx_add_column.xml" relativeToChangelogFile="false"/>
   ```

3. 每个 `changeSet` 必须幂等：建表用 `<not><tableExists/></not>`，加列用 `<not><columnExists/></not>`，初始化数据用 `<sqlCheck expectedResult="0">`，统一 `preConditions onFail="MARK_RAN"`。
4. **已执行过的 changeSet 不要修改**（校验和会冲突）。历史环境已执行过、本次又必须修改的，只能加 `validCheckSum ANY` 并新增补偿 changeSet（参考 `004`、`005`、`021`）。
5. `id` 全局唯一，格式 `cmr-{动作}-{对象}-{yyyyMMdd}`；`author` 写真实提交人；表、列都写 `remarks`。
6. MySQL 的 DDL 自动提交，一个 changeSet 里尽量只做一件事，避免执行到一半失败留下半成品。

## 七、常见故障

| 现象 | 处理 |
| --- | --- |
| 后端启动报数据源连接失败 | `docker start cmr-mysql`，确认 3306 已映射、Redis 服务已启动 |
| 打包报 `Unable to rename ...jar.original` | 旧后端进程仍占用 jar，按第四节的命令停掉后重打 |
| 打包报 `Cannot access ... in offline mode` | 命令里带了 `clean`，去掉即可；缺依赖则去掉 `-o` 联网拉取 |
| 新增 changeSet 未执行 | 检查是否已 `include`、`relativeToChangelogFile="false"` 是否漏写；`local` profile 下 `spring.liquibase.enabled=true` |
| 页面接口 401 | 用的是非 `local` profile，或没走 9849 的代理；本机联调固定带 `--spring.profiles.active=local` |
| 中文写库乱码 | SQL 命令漏了 `--default-character-set=utf8mb4` |
| 前端页面 404 | 地址缺上下文路径，应为 `http://localhost:9849/sdom-hsmty/` |
