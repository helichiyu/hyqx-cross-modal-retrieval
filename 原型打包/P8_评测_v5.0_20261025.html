研发需求说明

给研发

评测 = 用某个策略跑评测集，算指标，判断这个策略好不好；换策略再跑就是对比。

1 评测的定位

验证检索效果，判断策略改动是否有效。P5 改完 → P8 验证 → 再发布。

2 评测集从哪来

评测集 = 检索历史里的真实 query → 筛出「已暴露问题的 query」→ 人工标注标准答案（标出每条 query 下哪些结果对 / 错）→ 形成评测集。

链路：检索历史 → 新建评测集（勾选问题信号：零结果 / 无点击 / 复搜 + 业务场景 + 时间范围）→ 筛出这批 query → 生成「标注中」评测集 → 逐条标对 / 错 → 完成标注 → 「已完成」，工作台才可选。

评测集来源 = 从检索历史筛「问题 query」（零结果 / 无点击 / 复搜）+ 人工标注；标注完成前不可用。

为什么筛问题 query：专项评测集测「难点修好没有」，比通用评测集有用——通用集把难点摊平在均值里，看不出这几类 query 到底修没修好。

演示口径：筛出的 query 固定演示 8 条；标注面板只列前 4 条 query，标注完这 4 条即视为整批完成；「标注中」的评测集在下拉里置灰不可选。

3 指标怎么算出来

工作台 = 用「评测对象（某个策略）」去检索「评测集里的每条 query」→ 把检索结果和「标准答案」对比 → 算出召回率 / 精确率 / NDCG。

评测集提供「标准答案」，策略提供「检索能力」，两者一比才有指标；只有评测集没有对象，就没有检索结果可比；只有对象没有标准答案，就判断不了对错。

  • 召回率 Recall@5：该 query 的标准答案里，落进前 5 条的比例。
  • 精确率：返回结果里判对（命中标准答案）的条数，占返回条数的比例。
  • NDCG@10：按位置折损累计命中，命中越靠前得分越高；再除以理想排序，归一到 0–1。

每条 query 各算一遍再取平均，就是本次指标；同一评测集换评测对象再跑，就是两条策略的对比结果。

验收线从哪来：验收线＝业务定的目标值（当前演示：召回率 ≥ 0.90、精确率 ≥ 0.90、NDCG ≥ 0.85）；正式由业务/评测标准配置，页面只读取并判断达标 / 未达标。

4 评测对象、评测历史与报告

  • 评测对象：从策略管理（P5）来，可选当前生效策略 / 候选草稿 / 系统默认兜底；它只提供检索能力，不带标准答案。
  • 评测历史：每点一次「开始评测」就存一条记录（时间 / 评测对象 / 评测集 / 三项指标 / 结论），新记录插在最前；记录按当时的策略版本留存，旧版本下线后仍显示原名称。演示数据为两条历史记录，刷新页面后回到这两条。
  • 基线：取评测历史里「同一评测集」的最近一条，指标卡与报告都按它算涨跌；该评测集第一次评测时没有上一条，指标卡显示「—」，报告对比行也显示「—」。
  • 报告：给出本次评测结论，并逐项列出与上次评测的涨跌。

5 闭环

评测 → 发现短板 → 转策略调整（P5）→ 改完再评测。
