页面正文只保留 2 个业务块与主操作（反馈：登记反馈；运营推荐词：添加推荐词与逐词开关），模块编号与 F-CR 编号只在本说明中出现。 数据流、输入输出、价值句、来源句、块底口径与页面总结统一在本说明的「数据口径」段，正文只留控件、列表、状态与数据数字。

数据口径 · 逐条归档
  • 页面数据流：输入 = 反馈：检索历史 query（运营从分页列表选一条登记）+ 用户上报 + 零结果统计；运营推荐词：运营手动维护的词表（添加 / 删除 / 开关）。输出 = 反馈 → 策略调整 / 数据修正；运营推荐词 → 检索台联想。
  • 页面总结：运营从检索历史选 query 登记结果问题、形成反馈单后处理（反馈）→ 运营维护推荐词、直达检索台联想（运营推荐词）。
  • 反馈 · 口径：运营从检索历史选 query 登记「结果有问题」，形成反馈单，处理后改策略 / 改数据。登记时先在弹窗的检索历史分页列表里选一条 query（每页 10 条，可按 query 搜索，页码与上一页 / 下一页切换），该条带时间 / 结果数，再填反馈类型（结果不准 / 排序差 / 来源标错 / 零结果）+ 说明，来源标注「检索历史 · query」。
  • 反馈 · 来源：登记时记录来源（检索历史 / 用户上报 / 零结果），列表不单列「来源」列；系统统计仅作运营后台参考。
  • 反馈 · 价值与输入输出：反馈单 → 运营处理 → 改策略 / 改数据 → 下次结果变好。输入 = 检索历史 query + 用户上报 + 零结果统计 → 输出 = 策略调整 / 数据修正。
  • 反馈 · 块底口径：反馈单进入「待处理」，行内「处理」一次完成决定、执行单与核验；零结果 / 无点击 / 复搜的系统统计仅作运营后台参考。处理完即改策略或改数据，下一轮结果变好。
  • 反馈 · 数据数字：系统统计仅作运营后台参考。
  • 运营推荐词 · 口径：来源 = 运营手动维护（添加 / 删除 / 开关）；近 7 天搜索次数仅作参考；发布 = 每个推荐词的开关即时生效：开 = 生效进入联想，关 = 停推不进入。
  • 运营推荐词 · 数据口径：词表来自运营维护；近 7 天搜索次数仅作参考。

数据口径补充：反馈按「检索历史选 query → 登记 → 处理 → 改策略 / 改数据」一条链路承载，检索历史在弹窗内分页呈现（每页 10 条 + 搜索）。
