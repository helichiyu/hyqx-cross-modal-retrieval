# TODO: 数据接入回源化、移除质量卡点、数据不出域对齐 - 2026-11-12

## 需求描述

按 `docs/【数据流图】跨模态检索中心 · 系统数据流.md` 对齐三处实现偏差：

1. **接入改为回源**：平台只持有向量与元数据，不下载原始内容；检索命中后按上游地址拉取原数据。
2. **移除人工卡点**：数据流 3.1 明确「只做数据源与黑名单，不按数据集逐条评审，也不设人工卡点」，因此下线 402 数据集评分与 406 召回率校验，以及配套的人工裁决分支。
3. **数据不出域**：数据流 3.8 明确「下载与导出能力不做」，`原型v5对齐改造方案_2026-11-10.md` 第 150 行也要求移除批量下载与导出入口。

检索链路本身不改（408 召回、融合、重排、阈值均保持现状）。

## 实施方案

### A. 接入回源化

现状：`DatasourceService.ingest` 把每条模态内容下载到 `dataset/ds/{数据源编号}/{datasetId}/`，403 解析本地文件，检索侧再按 `sourceFile` 读本地副本。

目标形态：

- 接入只拉元数据（dataset 列表 + item 分页 + modals 声明），落库 `cmr_dataset` / 条目索引，不落文件本体。
- 403 解析改为按条目 `modals[].url` 流式取用：文本 `content` 直接入库，图片/音频/视频按需下载到临时目录解析后删除，或在算子侧支持流式输入。
- `meta.db` 的 `sourceFile` 语义由「本地相对路径」改为「上游 URL（或上游 item_id + modal 定位）」，`locator` 继续保留段/秒/帧定位。
- 检索结果读取：预览与文件访问改为服务端代理回源（后端代取后转流），前端不直连上游。
- `DatasourceService.contract()` 里「文件仍在来源方，检索按 ID 引用」的文案与实现对齐后不再矛盾。
- 注意：回源后检索的时延与上游可用性耦合，需要超时、失败降级（返回元数据 + 占位）与来源侧缓存策略。

### B. 移除 402 / 406 与人工卡点

- `BuildPipeline`：链路收敛为 401 → 403 → 404 → 405 → 激活，删除 402 评定分支（`suspend` / `reject`）与 406 投产校验分支（`pass` 才激活、否则 `stuck`）。
- 405 建完索引即置 `active`，同场景旧索引置 `retired`，数据集转 `searchable`（复用现有 `activate`）。
- 下线 `POST /datasets/{id}/adjudicate`、`POST /datasets/{id}/confirm-production` 与对应权限码、菜单按钮。
- 数据集状态机收敛：删除 `scoring` / `stuck` / `rejected` 三个状态（需评估历史数据迁移：存量 `stuck` / `rejected` 数据集如何回填）。
- `CmrDataset.score`、`decision`、`stuckReason` 是否保留待定（`score` 仍被质量等级 `qualityGrade` 引用，需一并决策）。
- 算子侧 402m / 406m 可保留在算子清单里但不再被平台调用，或同步从编排中移除。
- 402 / 406 相关测试（`EvaluationServiceTest` 外的管线测试、`SearchServiceQualityGradeTest`）需同步调整。

### C. 数据不出域对齐

- 移除 `POST /file/package` 批量打包下载（`FileController.packageFiles`、`FilePackageDTO`、前端 `SearchResultView.vue` 对应入口、`cmr:file:read` 的下载语义）。
- `GET /file?download=true` 改为仅预览（或整体下线 download 参数），禁止附件下载。
- 按 3.8 复核结果页、搜索结果摘要、收藏三处：只保留条目 ID、名称、分数与预览，不存、不传文件本体。
- 「采用/废弃」是否随导出入口一并移除，按 3.8 与原型口径再确认后执行。

## 验收标准

1. 接入一个数据集后，共享卷不新增原始内容副本，只新增向量索引与 `meta.db`。
2. 检索命中后可正常预览该条目（服务端回源），上游不可达时给出明确占位而非报错。
3. 建库链无人工卡点：接入校验通过后自动跑到索引激活，数据集直接进入可检索。
4. 平台不再存在 402 / 406 调用与 adjudicate / confirm-production 接口。
5. 全站无批量下载与导出入口，`cmr_result_item`、`cmr_task_summary`、`cmr_favorite` 均不含文件本体。
6. 后端 `mvn test`、前端 typecheck/build 通过。
