## 结论与实施边界

### 1. 前端需要专项优化

现有前端功能骨架完整，但界面主要是 Element Plus 默认风格，与原型差距明显，需要专项对齐。

主要差距：

- 当前侧边栏为深色 `#001529`，原型为白底、右侧细边框、浅蓝选中态。
- 当前全局背景为 `#f5f7fa`，原型为冷白蓝 `#f6f9fe`。
- 当前页面多为通用 `page-card + table`，原型有更强的页面结构：P1 大搜索 Hero、P2 双列筛选与结果卡、P5 三段工作台、P8 三段评测流。
- 当前交互状态、空状态、加载骨架、弹窗层次、 hover 微交互与原型不一致。
- 原型统一 8px 基础圆角、低阴影、细边框；当前 Element Plus 默认样式未统一覆盖。
- 业务编号已使用 monospace，但复制、展示密度、色彩层级仍需按原型统一。

### 2. 原型等价还原原则

后续前端优化按以下原则执行：

1. 视觉基准以原型 HTML 实际渲染为准，不以 Element Plus 默认样式再设计。
2. 允许并鼓励移植原型的 HTML 结构、CSS 类、token、动效、hover、弹层、浮层、锁定态、空态和演示交互。
3. 原型中的静态演示数据必须替换为真实后端数据；接口暂缺或数据为空时，保留原型对应空态/异常态。
4. 原型中的内联 JS 逻辑要拆成 Vue 状态、computed、watch 和事件处理，不能整页直接嵌入演示脚本。
5. 可复用结构抽成 Vue 组件或全局样式；页面专属结构保留在页面组件内，避免为了抽象破坏原型还原度。
6. Element Plus 只作为表单、消息、日期等基础能力来源，外观必须被原型样式覆盖，不能保留默认管理后台风格。
7. 每页完成后用 1440×900 / 1440×1000 截图与原型并排比对，并逐项核对原型交互状态。

### 3. 后端不建议立即大规模重构

`docs/前后端规范/01-总体技术方案.md` 已明确：在 hsmty 父工程与私服不可用时，后端按既定风险预案采用“裸 Spring Boot 3 单模块”，但命名、分层、表结构、API 形态遵守 hsmty 规范。

当前后端已经基本符合该 fallback 方向：

- Controller / Service / Mapper / DTO / VO / Entity 分层存在。
- API 前缀、返回信封、异常处理、Swagger 注解基本齐备。
- MyBatis-Flex、Liquibase 已落地；鉴权与登录按最新需求调整为不启用，相关临时实现需清理成明确的匿名访问方案。
- 业务域拆分为 auth、dataset、search、strategy、task、evaluation、operation、file、operator。

因此，不建议在本次 UI 优化期间做 multi-module 大重构。应先做定向整改，待 hsmty 父工程与私服可用、功能稳定后再评估是否拆分 client/core/start 模块。

### 3. 鉴权临时下线与配置治理要求

最新需求已明确：鉴权与登录功能暂时下线，但保留后续恢复能力。当前“后端硬编码 `permitAll` + 前端固定管理员身份”不够规范，应改为配置开关：`cmr.auth.enabled=false` 时匿名访问并注入固定系统管理员；`cmr.auth.enabled=true` 时恢复原有 JWT 登录与权限校验。

- 后端保留登录接口、JWT、Spring Security 与 `@PreAuthorize` 代码，通过 `cmr.auth.enabled` 控制启用；当前默认配置为 `false`。
- 前端继续暂不展示登录页，保持固定系统身份；后续恢复鉴权时恢复登录路由、守卫与真实用户信息加载。
- 审计字段、检索历史归属等原依赖用户的逻辑，需明确改为固定系统用户、空值或匿名用户策略，不能随机失效。
- `cmr_user`、权限、字典中的角色数据保留，作为后续恢复鉴权的基础数据，不做删除变更。
- `application.yml` 本地默认数据库账号曾改为 `root/123456`，不得提交远端；敏感配置只通过环境变量或本地未提交配置注入。

## 风险与决策

| 风险 / 问题 | 建议 |
| --- | --- |
| 原型 HTML/CSS/JS 可照抄，但演示数据与内联脚本不可直接照抄 | 移植视觉与交互结构，拆成 Vue 状态和真实 API 调用，保留原型渲染效果 |
| UI 改造与后端大重构同时进行风险高 | 先 UI 专项，后端只做定向整改；multi-module 拆分暂缓 |
| 原型路由表与当前路由存在单复数差异 | 先保持现路由可用，后续用别名/重定向对齐契约，避免破坏已有页面 |
| 鉴权只是暂时下线，不能删除恢复能力 | 用 `cmr.auth.enabled` 控制：`false` 匿名系统管理员，`true` 恢复 JWT 鉴权；敏感配置不入库 |
| P1/P2 原型信息密度高 | 分阶段还原，优先保证结构和主流程，再补齐演示态和次要弹窗 |
| 模型权重缺失导致真实检索不可完整验收 | UI 验收可用接口 mock/空态；算子链路验收需先准备权重 |
