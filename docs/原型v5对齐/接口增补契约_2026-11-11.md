# 原型 v5 对齐 · 前后端接口增补契约（2026-11-11）

> 目的：前端按原型 v5 补齐功能时，需要后端新增/调整的接口与字段，一次说清，前后端各自按此实现，避免二次对齐。
> 约束来源：`docs/【数据流图】跨模态检索中心 · 系统数据流.md`（业务规则）、`docs/前后端规范/新项目技术选型与环境复用框架_HSMTY对齐版.docx`（技术栈）。
> 通用：均在 `/hs-api/cmr` 之下，返回 `ApiResult` / `ApiPageResult`，Long 主键序列化为字符串；只增不改，不改已发布字段语义。

---

## 1. P1 检索台

| 项 | 契约 |
| --- | --- |
| 检索类型「全部」 | `POST search` 的 `targetModalities` 允许为空/缺省，语义=不限定目标模态（由 408 召回四模态后按策略融合）。移除 `@NotEmpty`。`SearchResultVO.targetModality` 允许为 `null`。 |
| 策略摘要 | 已有 `GET strategies/options`：`threshold`、`rerank`、`paramSummary`。无生效策略时返回空数组。 |

## 2. P2 结果页

`GET search/results/{resultSetId}` 的 `HistoryDetailVO` 增补：

```jsonc
{
  "history": { "...": "..." },
  "strategySnapshotJson": "…",
  "items": [ /* 不变 */ ],
  "excludedCount": 12,                       // 本次下发前被剔除的条数（黑名单/质量/策略过滤）
  "excludedItems": [                          // 明细，最多 100 条
    { "itemId": "…", "name": "…", "source": "…", "reason": "blacklist|quality|strategy" }
  ]
}
```

- 剔除规则不新增：沿用 `SearchService` 现有黑名单 + 策略过滤逻辑，只是把剔除项记录下来并返回。
- 结果集分页：前端在前端切页，接口不需要分页参数。

## 3. P4 数据源库管理

`DatasourceVO` 增补：

```jsonc
{
  "requiredOk": true,
  "missingFields": ["dataset_id", "modals"],   // 缺失的必填项，取值：dataset_id|name|item_count|modals
  "connectStatus": "connected"
}
```

`POST datasources/{id}/test` 返回增补逐字段结果（保留原字段）：

```jsonc
{
  "connected": true, "statusCode": 200, "latencyMs": 42, "message": "…", "testedAt": "…",
  "checks": [
    { "field": "dataset_id", "label": "数据集 ID", "ok": true, "detail": "ds-001" },
    { "field": "name",       "label": "名称",     "ok": true, "detail": "…" },
    { "field": "item_count", "label": "条目数",   "ok": true, "detail": "1200" },
    { "field": "modals",     "label": "模态字段", "ok": false, "detail": "缺少 modal/modality" }
  ]
}
```

黑名单（原型 4 字段，按 `datasetId` 去重；检索排除仍按来源名，数据流 3.4）：

- `POST datasource-blacklist` 入参：`{ "datasetId": "…", "name": "…", "sourceName": "…", "endpoint": "https://…" }`；`datasetId` 必填，`endpoint` 必须 `http://` / `https://` 开头且不含空格。
- `GET datasource-blacklist` 返回项保持 `id, datasetId, name, sourceName, endpoint, createTime`。
- 新增 `GET datasource-blacklist/summary`：`[{ "sourceName": "…", "count": 3 }]`，用于抽屉里按来源显示条数。

## 4. P5 策略管理

| 项 | 契约 |
| --- | --- |
| 阈值 | `PUT strategies/{id}` 入参新增 `threshold`（0.30–0.99）；**缺省时保留库中现值**，不得回落 0.60。新建缺省 0.60。 |
| 新建默认 | 四权重 50/30/10/10，`rerank=true`，`threshold=0.60`。 |
| 上线 | `POST strategies/{id}/online` 置为直接生效（`active`），不落 `draft`。已下线策略允许编辑与发布。 |
| 发布 | 发布沿用草稿版本号（有草稿则提升草稿），仅保留最近 10 个版本，多余物理清理。 |
| 版本名 | `StrategyVersionVO` 增补 `name`（发布时的策略名快照）。 |
| 全局一致性 | 新增 `GET strategies/consistency` → `{ "checks": [ { "key": "threshold", "label": "阈值区间 0.30–0.99", "ok": true, "detail": "2 个策略阈值越界" } ] }`，固定 5 项：阈值区间、权重合计 100%、权重非负、重排开关有值、默认策略存在且生效。 |
| 跨策略对比 | `GET strategies/{id}/diff` 新增可选参数 `compareId`（对比策略 ID，缺省=自身）；返回结构与现有 diff 一致，增补 `threshold` 与 `vector`（向量模型）两行。 |

## 5. P6 搜索行为

`GET search-behaviors` 参数增补：

- `keyword`：同时匹配 任务号 / 输入内容 / 操作人 / 重放来源任务号（原来只匹配 query_text）。
- `downCount`：`Boolean`，`true` 只返回 `downCount > 0` 的记录。
- `taskNo`：精确定位单条任务（`?task=` 定位用）。
- `replayOfTaskNo`：只看某任务的重新执行记录。

`BehaviorVO` 增补：

```jsonc
{ "replayOfTaskNo": "TASK251111A1B2C3", "sealed": false, "upCount": 0, "downCount": 2 }
```

失败任务（新增）：

`GET tasks/failed?pageNum=1&pageSize=10` → `PageResult<FailedTaskVO>`：

```jsonc
{
  "id": "…", "bizNo": "TASK251111A1B2C3", "queryText": "…",
  "failType": "engine|data", "failDisposal": "retry|isolate",
  "handling": "retrying|recovered|isolated",   // 重试中 / 已恢复 / 已转隔离
  "errorMsg": "…", "createTime": "2026-11-11 10:00:00"
}
```

- `handling` 口径：`retrying` = 引擎侧失败且仍在重试（status ∈ ready/running 且 retryCount>0）；`recovered` = 曾经失败后已成功（status=done 且 retryCount>0）；`isolated` = 数据侧失败已转隔离（failDisposal=isolate 或 status=failed）。
- 只读：系统自动处置，不提供人工改状态。

## 6. P7 结果运营

`POST feedbacks/{id}/handle` 入参 `{ judgment, disposition, resultNote }`，后端校验固定映射：

| entryType | 允许 judgment | 允许 disposition |
| --- | --- | --- |
| zero | `need_data`（固定） | `supplement`（固定） |
| mismatch | `data_bad` | `block` |
| mismatch | `match_bad` | `strategy` |

非法组合抛业务异常（`CommonResponseEnum` 或 `BizException`）。列表/详情返回的 `disposition` 在未处理时为空（前端显示「—」）。

## 7. P8 效果评测

`EvaluationDetailVO.metrics` 与每次重放指标行统一为：

```jsonc
{
  "items": 20, "downRate": 0.15, "top20AvgSim": 0.72,
  "top1Sim": 0.91, "top20Overlap": 0.85, "down": 3,
  "avgSim": 0.66, "elapsedMs": 812
}
```

- 新增计算：踩率（downCount/items）、Top-20 平均相似度、Top-1 相似度、Top-20 与基准重叠率。
- `GET evaluations/hard-cases?pageNum&pageSize` → `PageResult<{ taskNo, query, downCount, createTime, resultSetId }>`，难例样本集（点踩任务），同时用于「新建评测」候选记录。
- 退化判定：踩数上升 `>=`、踩率 +5% `>=`、结果数 −10% `<=`（边界按原型用 >= / <=）。

## 8. 任务号口径统一（P2/P3/P6/P7）

数据流定义任务号为 `TASK + yyMMdd + 6 位`，原型全站展示 `TASK…`；检索历史表内部业务号为 `SRH…`。为同时满足对外口径与内部主键约束：

- **对外字段一律为 TASK**：`BehaviorVO.taskNo`、`SearchSummaryVO.taskNo`、`HistoryVO.taskBizNo`、`FailedTaskVO.bizNo`、`EvaluationRowVO.baseTaskNo/latestTaskNo`、`HardCaseVO.taskNo`、`EvalMetricsVO.taskNo`、`FeedbackVO.sourceTaskNo`、`replayOfTaskNo`。
- **内部检索号随附下发**：`BehaviorVO.srhNo`、`SearchSummaryVO.srhNo`（`HistoryVO.bizNo` 保持 SRH 不变）。
- **入参兼容两种形态**：`search-summary/{taskNo}`、`seal`、`vote`、`feedbacks.sourceTaskNo`、`evaluations` 新建基准、`search-behaviors?taskNo/replayOfTaskNo` 均先按 SRH 精确匹配，未命中再按所属任务记录反查；赞/踩落库统一按 SRH，避免同一任务产生两套记录。
- **P3 摘要增补**：

```jsonc
{
  "taskNo": "TASK251111A1B2C3",
  "srhNo": "SRH251111XXXXXX",
  "taskStatus": "done|failed|ready|running",
  "errorMsg": "失败原因（失败任务空态展示）",
  "replayOfTaskNo": "TASK251111A1B2C3"   // 重放来源，普通检索为 null
}
```

- **失败任务回查**：`GET tasks/failed` 新增可选 `keyword`（任务号模糊），供 P3 按任务号定位失败原因。
