# 跨模态检索中心 · 部署与运维手册

> 适用版本：后端 `cmr-backend` 1.0.0、前端 `cmr-web`、算子 `cmr-operators:1.0`。
> 甲方现场只需修改 [deploy/.env](../deploy/.env) 与模型权重目录，不改代码、不改镜像。
> 算子自身的详细说明（依赖、模型下载、算子协议）见 [docs/部署说明.md](部署说明.md)。

---

## 1. 部署形态

`deploy/docker-compose.yml` 一次拉起 5 个容器：

| 容器 | 镜像 | 对外端口 | 职责 |
| --- | --- | --- | --- |
| `cmr-web` | `cmr-web:1.0`（nginx） | `${CMR_WEB_PORT:-8080}` | 静态页面 + 同源反代 `/hs-api` |
| `cmr-backend` | `cmr-backend:1.0`（JRE 21） | 仅内部 8080 | 业务 API、建库编排、鉴权 |
| `cmr-operators` | `cmr-operators:1.0`（Python） | **不映射**，仅内部 6300 | 9 个算法算子 |
| `cmr-mysql` | `mysql:8.0` | 仅内部 3306 | 业务库 `cmr`，Liquibase 自动建表 |
| `cmr-redis` | `redis:7-alpine` | 仅内部 6379 | 预留（当前 JWT 黑名单在进程内，单实例足够） |

网络暴露面：**只有前端端口对外**，算子 6300 从宿主机与浏览器均不可达（满足验收项）。

共享卷（后端与算子必须同时挂载，否则逻辑路径 `dataset/...`、`runtime/...` 对不上）：

```text
仓库根/dataset  →  两端 /app/dataset
仓库根/runtime  →  两端 /app/runtime
宿主机模型目录  →  算子 /weight（只读）
```

## 2. 前置条件

1. Docker Engine 24+、Docker Compose v2（`docker compose version` 可用）。
2. 磁盘：镜像约 4–6 GB；模型权重约 3–6 GB；`dataset/` 与 `runtime/` 按数据量预留。
3. 内存：建议 ≥ 16 GB（算子加载双通道向量模型 + 精排模型）。
4. 网络：构建阶段需访问 npm/镜像站；如需内网镜像源，请在构建前替换 `cmr-web/Dockerfile` 的 npm registry 与 Maven `settings.xml`。
5. 模型权重按算子文档放置为三个子目录：

```text
weight/
├── chinese-clip-vit-base-patch16/
├── clap-htsat-fused/
└── bge-reranker-v2-m3/
```

下载方式见 [docs/部署说明.md](部署说明.md) 第二节与 `scripts/download_models.py`。

## 3. 首次部署

在仓库根目录执行（每条命令单独一行）：

```bash
cp deploy/.env.example deploy/.env
```

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build
```

查看启动状态：

```bash
docker compose -f deploy/docker-compose.yml ps
```

验证（宿主机执行）：

```bash
curl -fsS http://127.0.0.1:8080/hs-api/actuator/health
```

浏览器访问 `http://<宿主机IP>:8080`，用内置账号登录：

| 账号 | 初始密码 | 角色 | 说明 |
| --- | --- | --- | --- |
| `admin` | `Cmr@2026` | 管理员 | 全权限 |
| `operator` | `Cmr@2026` | 运营 | 策略/评测/运营/库管理 |
| `user` | `Cmr@2026` | 检索用户 | 检索与历史 |

> **首登必须改密**：当前版本改密通过管理员在数据库中重置（BCrypt），后续版本提供页面。生产环境部署完成后请立即修改，并同步更换 `.env` 中的 JWT/AES 密钥。

## 4. 配置项（甲方只改这里）

全部集中在 `deploy/.env`：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CMR_WEB_PORT` | `8080` | 前端对外端口 |
| `CMR_DB_NAME` | `cmr` | 业务库名；首次启动由 MySQL 创建 |
| `CMR_DB_USER` / `CMR_DB_PASSWORD` | `cmr` / `cmr-change-me` | 应用库账号 |
| `CMR_DB_ROOT_PASSWORD` | `root-change-me` | MySQL root 密码 |
| `CMR_JWT_SECRET` | 示例值 | JWT 签名密钥，**≥32 字节**；更换后所有登录态失效 |
| `CMR_CRYPTO_KEY` | 示例值 | 数据源认证信息 AES 密钥（内部 SHA-256 派生，建议 ≥32 字节）；更换后已存认证信息无法解密 |
| `CMR_WEIGHT_DIR` | `../weight` | 模型权重目录（相对 `deploy/` 或绝对路径） |
| `CMR_JAVA_OPTS` | `-Xms512m -Xmx2g` | 后端 JVM 参数 |

算法侧参数（权重、topK、线值）在 `config.yaml` 与后端 `application.yml` 的 `cmr.eval.lines`，属于高级配置，一般不动；验收阈值 `cmr.eval.lines.recall` 默认 0.8。

## 5. 日常运维

### 5.1 日志

```bash
docker compose -f deploy/docker-compose.yml logs -f backend
```

```bash
docker compose -f deploy/docker-compose.yml logs -f operators
```

后端任务日志同时落库（任务详情页「执行日志」时间线），算子调用失败会区分引擎侧/数据侧并写入 `cmr_task.error_msg`。

### 5.2 健康检查

- 前端：容器 `HEALTHCHECK` 检测首页 200。
- 后端：`/hs-api/actuator/health`（仅容器内可访问），依赖 MySQL/Redis 健康。
- 算子：`/healthz` 返回各算子 `ok` 与输入输出目录可写状态。

### 5.3 数据备份

- 业务库：`cmr-mysql-data` 卷。备份命令：

```bash
docker exec cmr-mysql mysqldump -uroot -p"$CMR_DB_ROOT_PASSWORD" --single-transaction --default-character-set=utf8mb4 cmr > cmr_backup.sql
```

- 数据集与运行期产物：宿主机 `dataset/`、`runtime/` 目录，按文件系统策略备份；`runtime/` 内含上传文件、索引目录与评测文件。

### 5.4 升级

```bash
docker compose -f deploy/docker-compose.yml build --pull backend web
```

```bash
docker compose -f deploy/docker-compose.yml up -d
```

Liquibase 在后端启动时自动执行，变更脚本幂等；**已执行 changeSet 不允许修改**，升级只新增文件。

### 5.5 停止与清理

```bash
docker compose -f deploy/docker-compose.yml down
```

数据卷默认保留；如需彻底清理（谨慎）：

```bash
docker compose -f deploy/docker-compose.yml down -v
```

## 6. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 浏览器打不开 `6300` | 预期行为：算子仅内部网络可达，后端经 `http://operators:6300` 调用 |
| 后端启动失败，日志提示数据库连接 | 检查 `.env` 密码与 `cmr-mysql` 健康状态；首次启动 MySQL 初始化需 20–40 秒 |
| 建库任务失败「模型未加载/文件不存在」 | `CMR_WEIGHT_DIR` 未指向包含三个模型子目录的路径；或 `dataset/` 未挂载 |
| 上传数据集返回 413 | nginx `client_max_body_size` 已设 2 GB；更大的包请分卷或在反代层放宽 |
| 搜索超时 | 算子在线接口默认 15s 超时（`cmr.operator.timeout-search-ms`）；确认算子容器资源与模型已加载 |
| 登录后立即 401 | `CMR_JWT_SECRET` 被更换或后端重启后旧 token 失效，重新登录 |
| 评测结论为未达标 | 对照 `cmr.eval.lines.*` 阈值；报告页展示实测值/线值/未达标项 |
| 页面刷新 404 | nginx 已配置 `try_files ... /index.html`；若自行改反代需保留该规则 |

## 7. 安全基线

1. 仅开放前端端口；MySQL/Redis/算子/后端不映射宿主机端口。
2. `.env` 不入库；生产替换全部示例密钥，`CMR_CRYPTO_KEY` 必须 32 字节。
3. 所有业务接口经 Spring Security 方法级鉴权（`cmr:{资源}:{动作}`），未登录/无权限返回 401/403。
4. 内置账号首登改密；按角色分配 `admin/operator/user`。
5. 文件访问限定 `dataset/`、`runtime/` 白名单并防路径穿越；数据库只做逻辑删除。
