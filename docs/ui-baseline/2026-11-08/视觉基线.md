## 2. 全局视觉基线

原型 P1–P9 使用统一的“清爽冷白蓝”体系：

| Token | 原型值 | 当前实现 | 差距 |
| --- | --- | --- | --- |
| 工作区背景 | `#f6f9fe` | `#f5f7fa` | 当前偏灰，缺少冷蓝氛围 |
| 主色 | `#4169f6` | Element Plus 默认蓝 | 主色不一致 |
| 侧边栏 | 白底 + `#e6edf8` 右边框 | `#001529` 深色 | 差距明显 |
| 卡片 | 白底、细边框、低阴影 | Element Plus 默认卡片 | 层级和边界不一致 |
| 基础圆角 | `8px`，部分页面更大 | 默认控件圆角 | 圆角体系未统一 |
| 主内容 | 常用 `1200px` 最大宽度、页面专属留白 | `page-card + 12px margin` | 信息密度和节奏不同 |
| 文本 | 主文本 `#1f2937`，辅助 `#667085` | Element Plus 默认灰阶 | 层级不够贴近原型 |
| 交互 | hover、弹层、骨架、空态均有专门设计 | 以默认 Element Plus 状态为主 | 交互质感不足 |

## 3. 逐页差异清单

### P1 检索台

- 原型截图：[prototype/P1.png](prototype/P1.png)
- 当前截图：[current/P1.png](current/P1.png)

原型特征：

- 大型 Hero 区域作为全系统唯一查询入口；
- 80px 高度大搜索框，居中聚焦；
- 查询模态、目标模态和业务场景在主视觉区组成完整查询上下文；
- 4×4 模态矩阵是页面签名组件；
- 上传条与矩阵结合，文件识别后锁定查询模态行；
- 意图澄清浮层、推荐词联想、短query红字提示均有明确状态。

当前差距：

- 当前为常规 `el-card` 表单结构，缺少 Hero 和大搜索框；
- 权重、topK 等策略参数直接占据主界面，原型将主要注意力集中在“输入 + 模态 + 场景”；
- 未形成 4×4 模态矩阵签名组件；
- 上传区、文件卡片、识别中、识别失败等状态视觉弱于原型；
- 澄清弹层功能已有，但视觉与原型浮层仍有差距。

### P2 结果页

- 原型截图：[prototype/P2.png](prototype/P2.png)
- 当前截图：[current/P2.png](current/P2.png)

原型特征：

- 双列结构：左侧结果筛选，右侧结果区；
- 顶部结果集概要、采用 / 废弃、批量操作条；
- 质量等级、相似度阈值、来源、模态分组等筛选体系；
- 结果卡片网格、骨架加载、空结果诊断与处置入口；
- 反馈登记和处置方案弹层层次完整。

当前差距：

- 当前以概要卡 + 纵向条目卡为主，缺少左侧筛选栏；
- 缺少批量回源下载、清除选择、分组统计等原型操作；
- 空结果已有基础提示和零结果反馈，但缺少“过滤过严 / 语义偏离 / 覆盖缺失”等诊断结构；
- 结果卡片密度、媒体展示、来源与得分布局未达原型效果。

### P3 任务详情

- 原型截图：[prototype/P3.png](prototype/P3.png)
- 当前截图：[current/P3.png](current/P3.png)

原型特征：

- 顶部任务信息区与状态识别明显；
- 任务材料、结果、步骤说明分成多个内容卡；
- 页面结构强调“材料 → 处理 → 结果”的阅读路径；
- 上一页 / 下一页等上下游导航收在页面结构中。

当前差距：

- 当前以单卡片、描述列表和表格为主；
- 缺少原型式的任务顶部信息带和分层内容卡；
- 步骤日志、材料、输出的信息层级需要增强；
- 任务失败与成功的视觉状态差异不足。

### P4 库管理

- 原型截图：[prototype/P4.png](prototype/P4.png)
- 当前截图：[current/P4.png](current/P4.png)

原型特征：

- 缺少数据源条和流程线；
- 数据集、索引、任务详情的分组展示较弱；
- 弹窗和抽屉仍偏 Element Plus 默认样式。

- 原型截图：[prototype/P5.png](prototype/P5.png)

### P6 任务管理

- 原型截图：[prototype/P6.png](prototype/P6.png)
