# 跨模态检索中心 · 库表设计

> 库：MySQL 8，库名 `cmr`。表前缀 `cmr_`，所有表带审计六字段（id/create_id/create_time/update_id/update_time/del_flag），逻辑删除 `T/F`。
> 主键为雪花 ID（bigint，内部）；对外展示一律业务编号（biz_no，见 04 号段登记）。
> 字段类型按 MySQL 8；JSON 列用 `json` 类型。

| scene | varchar(64) | 业务场景（字典 cmr_scene） |
| status | varchar(20) | 状态机，见下 |
| stuck_reason | varchar(512) | 卡住原因（402 suspend / 406 fail / 治理异常） |
| file_root | varchar(256) | 原始文件逻辑目录（dataset/ds/{biz_no}） |
| meta_json | json | 401 report 摘要（可解码率/模态覆盖/条数率/失败清单） |
| score | decimal(6,4) | 402 评分 |
| decision | varchar(16) | 402 判定 pass/suspend/reject |
| item_count | int | 403 解析条目 |
| modality_json | json | 分模态条数 {text,image,audio,video} |
| current_index_id | bigint | 当前激活索引（可检索后） |

**status 状态机**（数据流 3.1，"不允许"即接口层拒绝）：

```
ingest(接入中) → scoring(评定中) → stored(已入库) → indexing(建索引中) → searchable(可检索)
scoring → stuck(卡住) [suspend]        stuck → stored(裁决通过) / rejected(裁决不通过)
indexing → stuck [406 fail]            stuck → searchable(确认投产)
scoring → rejected(已剔除) [reject]    rejected 终态
不允许：scoring→searchable；rejected→ingest
```

## 8. cmr_result_item 结果集条目（ID 快照）

> 口径见 05 决策记录：**只存「样本 ID + 名次 + 分数」，不存名称与内容**（文本段、文件路径、帧/秒定位均不落库）。
> 查看时按 item_id 回查**检索时索引**（`cmr_search_history.index_id`）的条目元数据取名称/预览；该索引元数据已被清理或条目不在其中时显示「已删除」占位。单次检索约 0.3 KB。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| search_id | bigint | 检索历史（加索引） |
| result_set_id | varchar(40) | 冗余 RST，便于直接按结果集查询 |
| result_rank | int | 名次（API 字段名 rank） |
| item_id | varchar(64) | 算子条目 ID（ITM 号，名称实时回查） |
| modality | varchar(16) | 模态（展示分组用） |

| 字段 | 类型 | 说明 |

## 检索日志保留策略（05 决策）

| 记录范围 | 口径 |
| --- | --- |
| 滚动删除 | `cmr_search_history` 及其 `cmr_result_item`、`cmr_click_event` 子记录，连同其 `cmr_task(type=search)` 及对应 `cmr_task_log`（防任务表无上界；build/eval 型任务不清理），按 create_time 30 天滚动清理（每日定时任务） |
| 永久保留例外 | 被"踩"/被标记/被溯源的检索——凡被 `cmr_feedback.search_id` 或 `cmr_eval_item.search_id` 关联到的检索（含结果条目、点击事件、关联 search 任务）不参与删除，供治理追溯与评测溯源（量可忽略） |
| 判定口径 | 无需新增字段：清理条件 = `create_time < NOW()-30d` 且 `id NOT IN (SELECT search_id FROM cmr_feedback UNION SELECT search_id FROM cmr_eval_item)` |
| 删除方式 | 物理删除（日志类数据无审计追溯要求，治理追溯由永久保留条目承担；为本库逻辑删除约定的显式例外） |

## 索引与约束要点

- 所有 biz_no 唯一索引；create_time 常规索引（列表按时间倒序）。
- cmr_search_history(result_set_id) UK；cmr_result_item(search_id, rank) 联合索引。
- cmr_strategy(scene, status) 上由应用层保证"同场景一条 active"（MySQL 可用函数索引辅助）。
- cmr_task(ref_id, type) 索引；cmr_click_event(search_id) 索引；cmr_feedback(search_id) 索引（滚动删除排除项查询）。
