## 一、总体架构

```
                        ┌────────────────────────────────────────────┐
 浏览器 ──HTTP:80─────▶ │ nginx（前端静态资源 + /hs-api 反代后端）      │
                        └───────────────┬────────────────────────────┘
                                        │ :8080
                        ┌───────────────▼────────────────────────────┐
                        │ cmr-backend（Java 21 / Spring Boot 3）      │
                        │  认证 JWT · 五业务域 · 任务编排 · 文件服务    │
                        └───┬───────────────────────┬────────────────┘
                            │ MySQL 8 / Redis        │ HTTP（内网）
                            │                        │ :6300
                            │              ┌─────────▼────────────────┐
                            │              │ cmr-operators（已交付）    │
                            │              │ 9 算子四协议 + /search     │
                            │              └─────────┬────────────────┘
                            │                        │
              ┌─────────────▼────────────────────────▼─────────────┐
              │ 共享数据卷（backend 与 operators 同名挂载）           │
              │  dataset/（入库原始文件）  runtime/（上传/输出/索引）  │
              └────────────────────────────────────────────────────┘
```

**调用链铁律**：浏览器只访问 nginx（静态资源 + `/hs-api`）；后端是唯一能到达 6300 的调用方；`runtime/...`、`dataset/...` 逻辑路径由后端拼共享卷根直接读文件。

## 二、技术栈与工程结构

### 后端（cmr-backend）

基线为 hsmty 模块规范（根目录 CLAUDE.md）；**当前 hsmty 模板工程与私服未到位，按既定风险预案以"裸 Spring Boot 3 单模块"先行**，但命名、分层、表结构、API 形态完全按 hsmty 规范执行（包 `com.hsmty.cmr`、表前缀 `cmr_`、路径 `/hs-api/cmr/...`、返回信封 `ApiResult`、逻辑删除、审计字段），模板到位后平移合并，契约不变。

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 语言/运行时 | Java 21（虚拟线程开启） | 长任务编排用虚拟线程，不占平台线程 |
| 框架 | Spring Boot 3.5.x + Spring MVC | 单模块可执行 jar |
| ORM | MyBatis-Flex | 与 hsmty 规范一致；`map-underscore-to-camel-case` |
| 数据库 | MySQL 8（库名 `cmr`，独立于平台库亦可并存） | Liquibase 管理（见 02 文档） |
| 缓存 | Redis（可选，首版仅用于登录态黑名单与推荐词缓存） | 不引入也可运行（降级为内存） |
| 鉴权 | 自实现 JWT（HS256）+ Servlet Filter + `@PreAuthorize` 风格拦截 | 三角色：admin/operator/user（见 04） |
| 密码 | BCrypt | 初始账号经 Liquibase 初始化 |
| 文档 | springdoc-openapi（生产关闭） | /hs-api/cmr/v3/api-docs |
| ID | 雪花主键（内部）+ 业务编号（前缀+yyMMdd+6 位 CSPRNG，见 04） | 对外一律业务编号 |

```
cmr-backend/
├── pom.xml
└── src/main/java/com/hsmty/cmr/
    ├── CmrApplication.java            # 启动类
    ├── config/                        # Web/Security/OpenAPI/MyBatis/任务执行器

    │   ├── search/                    # 检索域：检索编排、澄清、结果集、检索历史、任务
```

## 三、任务编排设计（建库链/评测链）

### 任务模型

- 表 `cmr_task`（见 02），type=`build`（建库）/`eval`（评测）/`search`（检索任务记录）。
- 执行器：`ThreadPoolExecutor`（虚拟线程工厂，并发 1——决策 14 建库并发 1；检索同步不进队列）。
- 步骤登记：`current_step` 记录 401…405 当前环节；每步开始/结束写 `cmr_task_log`（排查依据，兼作任务详情"材料"数据源）。

### 建库链状态机（对应数据流 3.1）

```
登记数据源 ─▶ 接入中(401) ─▶ 已入库 ─▶ 建索引中(403→404→405) ─▶ 可检索
                  │
                  └─ 数据源回源接入：只落 manifest.jsonl（元数据+条目 URL），不下载原始内容
```

- 按数据流 3.1「只做数据源与黑名单，不按数据集逐条评审，也不设人工卡点」：402 评定与 406 投产校验已从编排中下线，405 建完索引即自动激活。
- 增量数据：走同一链路新数据集，激活时同场景旧索引置 retired（保留回滚）。

### 失败分类（决策 11）

| 分类 | 判定 | 处置 |
| --- | --- | --- |
| 引擎侧 | 算子服务连接失败/超时/HTTP 5xx/信封 code=1 且非数据原因 | 自动重试，≤3 次（指数退避）；超限转隔离 |
| 数据侧 | 401 decodableRate 过低被 402 判 reject、文件无法解码、路径非法 | 不重试，直接转隔离，失败原因落库 |

重试与隔离状态落在 `cmr_task.fail_disposal`（重试中/已恢复/已转隔离），与数据流 3.3 一致。

### 评测链

`cmr_eval_record` + type=eval 任务：选评测集与评测对象（生效策略/草稿版本/系统默认）→ 调 409（带 weights/rerank 与 indexDir）→ 指标、结论、对比落库。

## 四、在线检索链设计

```
前端提交查询 ─▶ POST /cmr/search
                  ├─ 1. 407 查询理解（needClarify=true → 返回澄清选项，结束）
                  ├─ 2. 取当前场景生效策略版本（无则系统默认）
                  ├─ 3. 408 /search（携带 weights/rerank/topK/indexDir=激活索引）
                  ├─ 4. 结果集快照落库（cmr_result_item）+ 检索历史（SRH）+ 任务记录
                  └─ 5. 返回结果集（含 resultSetId、条目、策略快照、耗时）
```

- 澄清选定后前端带 `clarifiedQuery` 再次提交，跳过 407。
- 查询文件（以图/音/视搜）：先 `POST /cmr/file/upload`（落共享卷 `dataset/query/`）→ 拿逻辑路径提交检索。
- 再次执行（P9）：按历史记录原参数重放，生成新 SRH。
- 采用/废弃（P2）：仅未采用可操作，一次性终态。

## 五、文件服务与媒体预览

- `GET /hs-api/cmr/file?path=<逻辑路径>`：path 必须以 `runtime/` 或 `dataset/` 开头，resolve 后不得越出共享卷根（防穿越）；按扩展名给 Content-Type；支持 Range（音频/视频拖动）。
- 结果条目预览映射（05 口径）：名称/文件/段定位不随快照存储，查看时按 item_id 实时回查库内条目元数据——text→回查文本段；image→回查文件直接出图；audio/video→回查文件 + 段起止秒展示播放器；条目已删→显示「已删除」占位。
- 任务详情"材料"：任务日志 + 各环节输出文件（report.json/items.jsonl/eval_report.json）经同一文件接口只读展示。

## 六、部署拓扑（docker-compose 单机）

| 服务 | 端口 | 卷 |
| --- | --- | --- |
| cmr-web（nginx） | 80:80 | 前端静态资源；/hs-api → backend:8080 |
| cmr-backend | 8080（仅内网） | dataset、runtime（与算子共享）、app 配置 |
| cmr-operators（已交付） | 6300（仅内网） | dataset、runtime（与后端共享）、weight |
| mysql | 3306（仅内网） | mysql-data |

环境变量集中覆盖：数据库/Redis 连接、JWT 密钥、算子地址（`CMR_OPERATOR_BASE`，默认 `http://cmr-operators:6300`）。

## 七、安全设计

1. 登录发 JWT（12h），Filter 校验；登出加入 Redis/内存黑名单。
2. 接口级权限码 `cmr:{资源}:{动作}`（清单见 04），三角色映射。
3. 算子服务不对浏览器暴露；文件接口白名单 + 路径穿越校验。
4. 对外（URL/列表展示）一律业务编号，雪花 ID 不出内部链路（ID 规范第一层）。
5. 密码 BCrypt；数据源认证信息加密存储（AES，密钥走环境变量）。

## 八、非功能假设（决策 14，量级变化时重评）

| 项 | 假设 | 影响 |
| --- | --- | --- |
| 条目规模 | ≤50 万 | IndexFlatIP 够用；超出切 IVF/HNSW（算子侧配置演进） |
| 建库并发 | 1 | 单执行器；多任务排队 |
| 检索 QPS | <10 | 后端同步代理即可，无需缓存层 |
| 检索延迟 | 关精排 <2s / 开精排 <4s（含代理） | 前端 15s 超时 |
| 数据保留 | 检索日志（历史/结果条目/点击）30 天滚动删除，被踩/被标记的永久保留；runtime 任务目录按任务保留 | 磁盘 ≥200G |
