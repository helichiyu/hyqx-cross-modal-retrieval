# 原型 v5 与现状（hsmty-cmr/web + core）差异总清单

> 依据：`docs/原型v5/P1~P8` 静态原型逐页对照当前 Vue 实现与 Java 后端，2026-11-11 统一审计。
> 行号均指向审计时的工作区文件，实施前需按最新代码复核。
> 标记说明：**[前端]** 纯前端可改；**[前端+API]** 需补前端 API 封装；**[后端]** 需改 Java；**[需裁决]** 原型自身矛盾或与现有业务能力冲突，需产品/用户拍板。

---

## 0. 结论速览

| 类别 | 数量（条） | 说明 |
| --- | --- | --- |
| 全局壳层/设计令牌差异 | 10 | 影响全部页面，应最先统一 |
| 原型有、现状缺的控件/区域 | 52 | 其中 15 条需后端配合，其余纯前端 |
| 现状有、原型没有的控件/区域 | 23 | 其中 9 条是业务增强，是否删除需裁决 |
| 后端接口/规则缺口 | 14 | 集中在 P1 模态校验、P2 排除清单、P5 生命周期、P7 处置规则、P8 指标 |
| 明显实现缺陷（非 UI 对齐） | 6 | 侧栏收起失效、上传失败脏状态、阈值被静默覆盖、零结果默认判断错误等 |

最需要先看的五件事：

1. **P5 策略编辑没有阈值输入，保存会把已有阈值静默覆盖成 0.60** —— 会改坏线上检索结果。
2. **P7 零结果反馈默认被写成「调策略」**，原型要求固定「库里缺数据 → 补充数据」；且判断与去向可随意组合，后端也不校验。
3. **P1 缺「全部」检索类型**，且后端 `SearchExecuteDTO.targetModalities @NotEmpty` 会拦住不选模态对的检索。
4. **P1 检索台不是原型的一屏左右分栏**，Hero 与搜索框明显偏大，是「看起来差别最大」的直接原因。
5. **全局组件全部走 Element 默认皮肤**（表格/徽标/分页/弹窗/输入框），与原型手写组件在字号、圆角、边框、hover 上系统性不一致。

## 2. P1 检索台

### 布局/视觉
- 一屏两列 → 见 G1/G2；Hero `padding 54/46/38、radius 30、h1 clamp(40,4.2vw,54)` vs 原型 `26/28、radius 22、32px`；搜索框 `80px/radius 24` vs `60px/17`；模态矩阵 `76px+4列/42px格/gap7/max640` vs `56px+4列/44px格/gap6/max720`；澄清弹窗 540px vs 520px。

### 原型有、现状缺

| 控件 | 现状 | 缺口判定 |
| --- | --- | --- |
| 检索类型「全部」（默认） | 无，只有文/图/音/视频，且强制选模态对 | **[前端+API+后端]** `SearchExecuteDTO.java:35-36 @NotEmpty` 会拒绝空 targetModalities；`SearchService` 实际允许 null 由 408 四模态召回 → 放宽校验 |
| 策略摘要「阈值 0.60 · 重排开」 | 无 | **[前端]** `GET strategies/options` 已返回 threshold/rerank/paramSummary |
| 无生效策略回退提示 | 无 | **[前端]** options 空列表即可判断 |
| 联想「示例搜索」兜底、最近搜索/热门检索分组 | 只有「历史检索/运营热词」，统一 ≥4 字触发 | **[前端]** |
| URL 回参 `pair/stg/relax` + `localStorage.cmRefill` | 只读 `q` | **[前端]** |
| 澄清记录会话持久化（sessionStorage，60 条） | 内存 Set，刷新即丢 | **[前端]** |
| guest/无库权限拦截 | 无 | **[前端]** `auth/me` 已有 permissions |
| 上传失败状态复位 | 只置 fail，不清 queryFile/queryMode | **[前端]** 缺陷：可能用旧文件发起检索 |

### 现状有、原型无
- 业务场景下拉（`cmr_scene`）、配置 ↗ 链接、澄清浮层「场景建议」标签 —— **[前端]** 建议删（或 **[需裁决]** 若场景是后端必需则保留并说明）。

### 交互偏差
- 矩阵再次点击同一格会取消选择（原型不取消）；清空不重置策略与场景；检索不携带 `pair/stg` 到结果页；澄清触发完全依赖 `understand.needClarify`（原型本地 <4 字规则）。

## 7. P6 搜索行为

### 区域
- 原型两块：搜索行为流水 + **失败任务**；现状只有流水 + 屏蔽条目 + 原因分析弹窗，失败任务藏在隐藏路由 `/tasks`。
- 流水表：原型 8 列固定宽（时间首列 / 任务号 / 操作人 / 模态对 / 输入内容 / 结果数 / 赞踩 / 操作）→ 现 10 列（新增策略、状态，时间移到倒数第二）。

### 原型有、现状缺

| 控件 | 缺口判定 |
| --- | --- |
| 失败任务整块（6 列、重试中/已恢复/已转隔离徽标、每页 10） | **[前端+后端]** 现有任务接口按 `status=failed` 查，会漏掉被置回 `ready` 的「重试中」；TaskVO 无 queryText |
| 操作列「详情 + 重新执行」 | **[前端]** `GET /tasks/{id}`、rerun 接口已有；现为「摘要/封存/原因分析」 |
| 有踩/无踩 chips | **[后端+前端]** behaviors 无 downCount 参数 |
| 单一搜索框覆盖操作人/输入内容/任务号/重放来源 | **[后端+前端]** keyword 只 like query_text |
| 重放来源「⟳ 重放自 TASK…」 | **[后端+前端]** behaviors 未返回 replayOfTaskNo |
| 任务号不可点、可复制 | **[前端]** 现为跳摘要链接 |
| 空态「清除筛选」、`?task=`/`?tab=fail` 定位 | **[前端]** |

## 10. 后端缺口汇总（按影响排序）

1. **[P5]** 保存策略未带 threshold 时按默认 0.60 回写 —— 覆盖既有阈值。
2. **[P7]** `FeedbackService.handle` 缺 entryType↔judgment↔disposition 校验；零结果单可被写成「调策略」「屏蔽数据」。
3. **[P1]** `SearchExecuteDTO.targetModalities @NotEmpty` 与「全部」检索类型冲突。
4. **[P2]** 结果集接口不返回被剔除条目计数/明细，「本次共排除 N 条」无法实现。
5. **[P2/P7]** 空结果处置无状态机（owner/due/待处置→处置中→已闭环）与原因分析结论字段。
6. **[P5]** `online` 把状态置 `draft`（原型要求直接生效）；已下线策略禁止编辑/发布；publish 总 +1 不沿用草稿版本。
7. **[P5]** 一致性检查只有单策略口径，无全局 5 项；diff 不支持跨策略；版本无 name 快照。
8. **[P6]** behaviors 不返回 replayOfTaskNo，不支持 downCount / taskNo 过滤。
9. **[P6]** 失败任务按 `status=failed` 查询漏掉「重试中」；TaskVO 无 queryText。
10. **[P4]** 数据源列表只返回 `requiredOk` 布尔，缺 missingFields。
11. **[P8]** 缺踩率、Top-20 平均相似度、Top-1、Top-20 重叠四项指标。
12. **[P1/P4]** `ingest` 前端无封装；`test` 前端未调用（均为接口已有）。
13. **[P2]** 结果集接口无分页参数（Top50 口径）。
14. **[全局]** 部分 Controller/DTO 与原型白名单/权限口径需复核（原型的 guest 拦截在现状无对应权限码）。
