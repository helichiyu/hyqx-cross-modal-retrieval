研发需求说明

给研发

以一条历史搜索记录为基准，追踪后续每次重新执行的效果变化。

1 定位

一条评测 = 一条历史搜索记录（基准）+ 之后每次重新执行的结果（重放）。它只回答一个问题：这条搜索现在比当时好，还是差。

评测列表用表格展示，每行一个评测，6 列：Query / 基准（该次任务：时间 · 条数 · 踩数）/ 重放（显示「N 次」）/ 最新（条数 · 踩数，无重放为「—」）/ 结论 / 操作（重新执行 · 查看对比）。表格上方可按 Query 搜索（不区分大小写、包含匹配）+ 结论筛选 chip（全部 / 已劣化 / 正常 / 未评测，带数量），每页 10 条，底部给「共 N 条」+ 上一页 / 页码 / 下一页。

结论列：已劣化（红字 + 整行浅红底）/ 正常（绿）/ 未评测（灰，无重放）；鼠标悬停显示判定原因。

检查评测数据：「评测列表」标题行右侧的按钮，打开后只读检查 4 项，弹窗给「✓ 评测数据检查通过」或「⚠ 发现 N 项问题 + 第 X 项需处理」，不改任何数据、不写存储：

  • 样本够不够：评测数 ≥ 1 且各评测基准的摘要条目合计 ≥ 10 条；显示「N 个评测 · 共 M 条样本」。
  • 有没有重复用：同一个条目 ID 出现在 ≥ 2 个评测的基准里，列出被共用的条目。
  • 样本还有效吗：基准条目在 cm_blocked_items（已屏蔽）或其来源在 cm_blacklist（来源进黑名单）。
  • 评价矛盾吗：同一个条目 ID 在不同任务里既被赞过又被踩过。

不统计大盘：没有汇总指标、没有趋势图、没有排行。

2 数据来源

  • 基准：搜索行为里的一条记录 —— 时间、query、结果数、该次结果的赞数 / 踩数；也可从难例样本集点「加入评测」设为基准（query 不在搜索记录里时按样本信息补一条基准）。结果页落盘摘要后，结果数 / 平均相似度 / Top-1 / 重合率按摘要真算。
  • 重放：同一条 query 点「重新执行」生成的记录；每执行一次，该评测重放次数 +1（结果页返回后合并 cm_eval_replays）。
  • 赞数 / 踩数：结果页单条结果的赞 / 踩，按任务号归到对应搜索记录后求和（取 cm_item_votes 的 up / down 条目数）。
  • 无摘要时：结果数、Top-20 平均相似度、Top-1 分数、Top-20 重合率走演示规则并带 demo，不请求真实引擎。

3 指标与来源

指标来源
结果数该次摘要的 items 条数（cm_task_summary）；无摘要时回落演示值
赞数该次搜索结果里被点赞的条目数
踩数该次搜索结果里被点踩的条目数
踩率踩数 ÷ 结果数；赞数与踩数都为 0 时显示「—」
Top-20 平均相似度摘要 items 的相似度均值；无摘要时回落演示值
Top-1 分数摘要 items 的相似度最大值；无摘要时回落演示值
Top-20 重合率本次与基准 items 的条目 ID 交集 ÷ 基准条数；无摘要时回落演示值

演示角标：只有结果数 / Top-20 平均相似度 / Top-1 分数 / Top-20 重合率 4 项会带「演示」角标；赞数、踩数、踩率不在角标范围内（赞 / 踩有记录时取 cm_item_votes 的条目数，种子评测的基准赞踩为演示值）。角标按行判断 —— 基准没有 cm_task_summary，或该行显示的重放记录里只要还有一条带 demo，就标「演示」；两边摘要齐全、指标真算时不标。

真实实现：结果页写 cm_task_summary（任务号 + q / time / n / pair / stg / thr + items：ID / 名称 / 来源 / 相似度 / 模态）→ 评测按基准与重放两边摘要重算结果数、平均相似度、Top-1、重合率。

相似度可比性：当前向量模型固定（CLIP双塔 v3），同一 query 的相似度分数跨次可比；模型不变的前提下，分数变化才代表效果变化。

踩率口径：踩率 = 踩数 ÷ 结果数；当赞数与踩数都为 0 时显示「—」（表示没有用户评价，不代表效果好）。

4 指标如何算

  • 赞数、踩数：该次搜索直接产生，取 cm_item_votes；
  • 踩率 = 踩数 ÷ 结果数；赞数与踩数都为 0 时显示「—」；
  • 结果数 = 本次摘要 items.length（基准与重放同口径）；
  • Top-20 平均相似度 = items.map(sim) 之和 ÷ n；
  • Top-1 分数 = Math.max(...sims)；
  • Top-20 重合率 = |本次 items 的 ID ∩ 基准 items 的 ID| ÷ 基准条数；
  • 无摘要时上述 4 项回落演示值并带 demo 标记（结果数＝基准结果数 − 3；平均相似度 / Top-1 在基准上 +0.01；重合率约 0.80 或在上一基础上 −0.05）；有摘要时记录里不写 demo。

5 对比与着色

  • 对比视图是指标对比表：行 = 指标，列 = 基准 + 最近 3 次重放 + 变化（最新 vs 基准）。
  • 对比视图固定显示「基准 + 最近 3 次重放」，历史重放不逐列铺开，避免列无限增长；完整重放记录以列表行内的「重放 N 次」为准。
  • 赞数上升为绿、下降为红；踩数、踩率下降为绿、上升为红。
  • Top-20 平均相似度、Top-1 分数上升为绿，下降为红；两者带「演示」角标时，颜色只示意口径，不代表真实变化。
  • 结果数只作参考，不按好坏着色：结果数受筛选条件影响，↓ 不一定坏。
  • Top-20 重合率基准为「—」，只比重放与基准的重合程度，不参与好坏判定。
  • 结论一句话按最新一次重放 vs 基准生成，同时写出踩数与平均相似度的变化，固定显示在对比表下方（有效 / 变差 / 改善 / 退步 / 无明显变化 5 种文案）。
  • 劣化时对比表下方先出现阻断提示「本次重放相较基准已劣化：踩数 / 踩率 / 结果数 …」，再是结论句；正常时提示「本次重放未发现劣化」。阻断只提示、不拦截操作。

6 重新执行与会话记录

  • 「＋ 发起评测」→ 从搜索行为记录里选一条 →「设为基准」，进入列表最前。候选列表 4 列（时间 / 查询 / 结果数 / 踩数），可按查询或时间搜索，已在评测中的 query 标「已在评测中」；同一 query 只保留一条评测，重复选择提示「该搜索已在评测中」。
  • 行内「重新执行」→ 结果页：带 query、replay=1、基准结果数（was）、新任务号与 back=P8；任务号 = TASK + yyMMdd + 6 位大写字母数字，避开已有号。
  • 基准有 cm_task_summary 时按摘要真算指标；基准无摘要时走演示规则（结果数＝基准 − 3、平均相似度 / Top-1 约基准 +0.01、重合率约 0.80）并带 demo；结果页落盘新任务摘要后回到本页，两边摘要齐全再重算并去掉 demo。
  • 在结果页点赞 / 踩后回到本页，该评测重放次数 +1，最新赞数 / 踩数取该任务号下被赞 / 踩的条目数。
  • 评测列表存在 sessionStorage 的 cm_evals：加入评测 / 发起评测后持久，刷新与返回不丢；清空该键回到内置种子列表。
  • 重放记录按 query 分组写入 sessionStorage 的 cm_eval_replays：任务号、时间、结果数、赞数、踩数、平均相似度、Top-1、重合率、演示标记（demo）；本页加载 / 结果页返回时合并。基准与重放任务两边都有 cm_task_summary 时按摘要重算并去掉 demo；任一没有摘要时保留演示值并带 demo。赞数 / 踩数取该任务号下的真实赞踩。

7 难例样本集

定位：从结果页单条点踩自动汇总的难例，用于专测薄弱点，不做人工标注；一行 = 一个 query。标题行「?」展开页内同一份口径。

5 列：Query / 被踩条目 / 被踩条目数 / 最近时间 / 操作（加入评测）。被踩条目只显示 1 行，超出截断，悬停看全部；被踩条目数 = 该 query 下去重后的被踩条目数（同一条被踩多次只算 1 条），不统计点踩次数。

排序与分页：被踩条目数降序（最差在前），同数量按最近时间倒序；每页 10 条（「共 N 条」+ 上一页 / 页码 / 下一页）；无数据显示「暂无被踩的数据」。

数据来源：cm_item_votes（点踩）+ cm_task_meta / cm_task_summary / cm_replay_records / cm_eval_replays（任务号还原 query、时间、条数与条目名称）；无数据时显示空态。

加入评测：点「加入评测」复用「设为基准」逻辑，直接进评测列表最前；已在评测中的 query 按钮禁用并显示「已在评测」。

局限：只覆盖被点踩的样本，不能代表整体效果；平台不做标注，因此不构成评测集。

8 说明

基准与重放取自真实搜索记录；赞数 / 踩数 / 踩率有赞踩记录时为真实值（种子评测的基准值除外）；结果数、Top-20 平均相似度、Top-1 分数、Top-20 重合率在有摘要时为真算，无摘要时回落演示值并在对比表标「演示」角标。

本期只做单条评测的判断与提示，不做大盘汇总、趋势与排行。

边界：只对已有基准做重放对比，不自动回滚、不改策略、不改上游数据；一次重放对应一个新任务号，可凭 cm_task_summary / cm_item_votes 追溯。

上下游：上游 搜索行为（基准候选）与 结果页（写 cm_task_summary / cm_item_votes）；下游 策略管理（把劣化提示作为调参输入）。

9 回归阻断

目的：重放后自动比对基准，判断是否劣化，避免「越改越差」还照常发布。

判定：踩数上升 / 踩率 +5% / 结果数 −10%，任一成立即劣化；都不成立为正常，无重放为未评测。

处置：劣化时在对比视图给出阻断提示（提示，不强制拦截）；列表可按「已劣化」筛选。

说明：本期只做判断与提示，不做自动回滚。
