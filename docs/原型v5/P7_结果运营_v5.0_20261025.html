研发视角

页面正文只保留反馈一个业务块：常规只在列表里处理已有反馈单； 唯一的登记入口是结果页「空结果处置 · 需求登记」带 ?zero= 进来（自动弹登记窗，类型固定「零结果」），本页不提供常驻的「登记反馈」按钮。 反馈单的类型由入口决定（标记不匹配 / 零结果）；去向由处理时的处理判断决定，且必须是平台能执行的动作。 平台是检索层：不修改上游数据，也不改写上游库内容。

三条去向，都是平台能落地的
  • 数据本身有问题 → 屏蔽数据：进屏蔽列表，检索时自动排除，立即生效。
  • 数据没问题、是匹配/排序问题 → 调整策略：数据保留，不写屏蔽列表，只记状态，作为 策略管理 调参与 效果评测 的输入。
  • 零结果 → 补充数据：记录数据需求给上游，平台不自己补数据。

处理弹窗：判断单选，去向只读
  • 弹窗字段：反馈单（单号 · query）/ 来源（结果摘要 / 空结果处置 · 来源任务号）/ 类型，均只读；标记不匹配且带标记条目时多一行「标记条目」（ID + 名称）。
  • 类型：由入口决定，登记弹窗与处理弹窗里都只读展示，不提供类型下拉。
  • 处理判断：标记不匹配给两个选项（数据本身有问题 / 数据没问题，是匹配/排序问题），默认「数据本身有问题」；零结果不给单选，固定一行「库里缺这类数据 → 补充数据」。
  • 去向：只读，跟着判断变 —— 数据本身有问题 → 屏蔽数据；匹配/排序问题 → 调整策略；零结果 → 补充数据。
  • 提交：底部按钮「标记已处理」；保存后状态转「已处理」、去向落定、按去向给 toast；列表里已处理行的操作按钮变为禁用的「已处理」。
  • 点踩：结果页单条点踩只用于统计（搜索行为 的「赞 / 踩」列），不生成反馈单，本页不读点踩数据。
反馈 · 记录字段
  • 列顺序（8 列）：时间 / 反馈单 / 搜索词 / 类型 / 条数 / 去向 / 状态 / 操作
  • 时间：反馈生成时间，YYYY-MM-DD HH:mm；第一列，列表按时间倒序（最新在上）
  • 反馈单：反馈单号（FBK + yyMMdd + 6 位安全码），单行显示
  • 搜索词：该反馈单的 query，单行，超出省略，悬停显示全量
  • 类型：由入口决定，只读（标记不匹配 / 零结果）
  • 条数：该反馈单涉及的标记条目数，显示「N 条」；零结果没有标记条目，显示「0 条」
  • 去向：处理完成后才显示，由处理判断决定，只读；屏蔽数据显示「屏蔽数据 · 已生效」；未处理一律显示「—」，不预填
  • 状态：待处理（橙） / 已处理（绿），只有这两态
  • 排序与分页：按时间倒序（最新在上），每页 10 条（「共 N 条」+ 上一页 / 页码 / 下一页）；无数据显示「暂无反馈单」
  • 操作：处理（选处理判断 → 标记已处理；零结果无需选择，直接标记已处理）
来源带入与回写
  • 标记不匹配：搜索结果摘要提交时写入浏览器会话存储（cm_mismatch_feedbacks），本页按反馈单号去重后并入列表最前
  • 零结果：以 ?zero= 任务号带入，本页自动打开登记弹窗（类型固定「零结果」、说明预填「检索无结果，疑似语料缺失」），登记窗内可按 query 搜索历史搜索记录（每页 10 条）选一条作为关联搜索，提交后生成反馈单
  • 回写：处理结果（st / judge / to）写回存储，刷新后该反馈单仍为已处理，去向不变
  • 屏蔽列表只在一种情况写：处理判断为「数据本身有问题」且该反馈单带标记条目时，才把条目 ID 写入 cm_blocked_items（数组，去重）；「调整策略」只改状态与 judge、不写屏蔽列表；「补充数据」只记录需求、不写任何存储
屏蔽的作用范围
  • 屏蔽：该条目进入屏蔽列表，结果页渲染前读取并过滤，立即生效；上游数据本身不变。
  • 确认：不经过数据源库管理二次确认，本页处理完成即生效。
  • 数据集级黑名单：由数据源库管理的「黑名单」按来源名整库屏蔽，与本页的单条条目屏蔽是两件事、独立生效；结果页把两类排除合并显示「本次共排除 N 条」。
页面入口与上下游
  • 入口：结果页「标记不匹配」提交后带 cm_mismatch_feedbacks 进来（按反馈单号去重、并入列表最前）；空结果处置带 ?zero=任务号 进来并自动弹登记窗。
  • 返回：带 ?back=P2 时顶部显示「← 返回结果页」，带回本次任务号（优先 task / zero，兜底取在册反馈单的来源任务号）。
  • 上游：结果页（标记不匹配 / 零结果）。下游：「屏蔽数据」→ 结果页按 cm_blocked_items 过滤；「调整策略」→ 策略管理 调参 + 效果评测 验证；「补充数据」→ 记录需求给上游。
