给研发

本页是用户搜索行为流水：一条搜索一条记录，不做跨记录的统计与聚合；每条记录只留两个结果：结果数与赞 / 踩。更深的运营与评测在 结果运营、效果评测。

列取值与说明

任务号本次搜索的任务编号（TASK…），紧接时间列独立一列；等宽字体、单行、可整体选中复制，不可点；查看详情走操作列「详情」

结果数该次搜索返回条数（130 / 87 / 42）；未搜到为「—」
赞 / 踩同一格显示「赞数 / 踩数」（如 3 / 5），按任务号汇总该次结果中被点过赞 / 踩的条目数；两者都为 0 时灰色显示「0 / 0」，无结果数为「—」
操作「详情」跳任务详情页；「重新执行」生成一条新任务记录并跳结果页；表格行本身不承接点击

重放来源不是独立列：有重放来源时，任务号下方追加一行小灰字「⟳ 重放自 TASK…」，纯文本标注原任务号，不可点。

记录来源（三类，按 task 去重）：①真实搜索——结果页加载时写 cm_task_meta（任务号 → query / 时间 / 操作人 / 模态对 / 结果数）；②重新执行——本页写 cm_replay_records（最多保留 100 条）；③演示数据——内置 12 条。加载时先并入重放记录、再并入真实搜索（合并时按任务号去重，同号以先到者为准、重放优先），列表展示上真实搜索排在演示数据之前；从结果页返回 / bfcache 恢复（pageshow）时重新读一次存储。

记录边界：本页只记用户搜索行为，一条行为一条记录；编辑策略、屏蔽数据等其他操作不记在本页。赞 / 踩落在数据条目上，本页只按任务号汇总条目数，不记单条明细。

不设状态：搜索记录不设成功 / 失败状态：结果数有值即搜到了，为「—」即未搜到。失败任务单独在页面「失败任务」表展示，其处置状态独立保留。

赞 / 踩口径：结果页按「任务号 + 条目号」写入 cm_item_votes；本页按行任务号统计 up / down 的条目数（同一条多次只算 1 条），不统计点击次数。存储里一条赞踩都没有时写入演示种子；新任务号默认 0 / 0。

重新执行：点「重新执行」生成一条新记录：新任务号（TASK + yyMMdd + 6 位大写字母数字，避开已有号）、当前时间、结果数＝原结果数 − 3（最小 0，演示模拟优化后结果收敛）、赞 / 踩 0 / 0；操作人 / 模态对 / 输入内容继承原记录，并写「⟳ 重放自 原任务号」。记录写入 cm_replay_records 后跳转结果页（q、pair、replay=1、was=原结果数、task=新任务号、back=P6）；同一 query 重放几次就有几条记录，可据此看出被重放过几次、结果数与赞 / 踩如何变化。

详情与快照：「详情」→ 任务详情页（任务号带入）。详情只存 Top-20 摘要（ID + 名称 + 分数），不存图片本体，保留 30 天；本页不存结果快照，「重新执行」只存条件与新结果数，在结果页看「当时 → 现在」的对比。

排序与筛选：固定按时间倒序（最新在上）；「全部 / 有踩 / 无踩」chip（有踩＝踩数 > 0；无踩＝踩数 = 0 或「—」）+ 搜索框（按操作人昵称 / 账户名、输入内容、任务号、重放来源，包含匹配、不区分大小写）叠加过滤；每页 10 条；无结果时给「清除筛选」。

失败任务（只读）：表格 6 列：任务ID / Query / 失败原因 / 失败类型 / 系统处理 / 状态；演示 3 条。失败由系统自动处理——引擎侧失败自动重试（最多 3 次），数据侧失败自动转隔离区；状态取「重试中 / 已恢复 / 已转隔离」，本页不提供人工处置；每页 10 条。

权限：本页为管理员页面，正式由登录态与库授权决定访问权限。演示态左下角可切换「管理员 / 只读」：切到只读后正文隐藏、显示「当前账号无管理员页面权限」遮罩并自动关闭研发说明抽屉。

入口与跳转：支持 ?task= 定位一条搜索记录（自动把搜索词填入搜索框并滚动到列表）、?tab=fail 定位失败任务表；上游来自 结果页（写 cm_task_meta / cm_item_votes），下游去 任务详情、结果页重放、结果运营 与 效果评测。图搜类 q 取文件名；无结果数（「—」）时原结果数按 0 计；条目屏蔽与数据集黑名单分别由 P7 / 数据源库管理 生效，本页只做展示。
