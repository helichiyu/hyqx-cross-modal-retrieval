## 1. 差异总览（旧实现 → 新原型）

### 1.1 信息架构

| 维度 | 现状（cmr-web） | 新原型 / 新数据流 | 处理 |
| --- | --- | --- | --- |
| 菜单 | 检索台、检索历史、库管理、策略管理、任务管理、结果运营、效果评测（7 项） | 检索台、数据源库管理、策略管理、搜索行为、结果运营、效果评测（6 项） | 删“检索历史、任务管理”菜单；新增“搜索行为”；“库管理”改名“数据源库管理” |
| 页面 | 9 个（P1–P9） | 8 个（P1–P8），结果页与摘要页为二级页不进菜单 | 删 P9；P3 由任务详情改为搜索结果摘要；P6 由任务管理改为搜索行为；P8 评测整体重做 |
| 任务模型 | 建库/检索/评测统一 `cmr_task`，任务管理是主入口 | 任务号只服务检索与重放；建库不设人工卡点；失败任务单独一张表 | 任务详情保留给失败任务排障，不再作为主页面 |
| 检索历史 | 独立 P9，采用状态 + 结果回看 | 并入 P6 搜索行为（一条检索一条流水） | P9 路由 301 到 `/behaviors`，代码下线 |

### 1.2 逐页差异

| 页面 | 现状 | 新原型要求 | 改造量 |
| --- | --- | --- | --- |
| P1 检索台 | 业务场景下拉 + 模态矩阵 + 澄清 | **检索策略下拉**（系统默认/训练取样/业务素材/日常检索）+ 参数摘要“阈值 0.60 · 重排开”；场景概念退出 P1 | 中 |
| P2 结果页 | 采用/废弃、批量下载、反馈登记、点击埋点 | **赞/踩、收藏、封存**；黑名单 + 条目屏蔽过滤清单；零结果三处置（放宽/换 query/登记需求） | 大 |
| P3 任务详情 | 任务信息 + 步骤日志 + 材料 | **搜索结果摘要**：8 项任务信息（含策略名+版本）+ Top-20 表 + 勾选不匹配 + 提交封存；30 天过期空态 | 重写 |
| P4 库管理 | 数据源 + 数据集列表 + 评定/裁决/投产/索引激活 | **只有数据源列表 + 黑名单抽屉**；4 项必填测试连接、向量化计数、手动同步；无数据集评审 | 重写 |
| P5 策略管理 | 策略 CRUD/草稿/发布/回滚/一致性 | 保留；补“系统预置不可下线、下线原因、下线/上线、阈值参数、版本保留 10 个、运维弹窗 diff” | 中 |
| P6 任务管理 | 任务分页 + 状态 + 失败表 | **搜索行为流水**：时间/任务号/操作人/模态对/输入/结果数/赞踩 + 详情/重新执行；失败任务表保留处置状态 | 重写 |
| P7 结果运营 | 4 种反馈类型、待处理/处理中/已闭环、推荐词 | 2 个入口（标记不匹配/零结果）、2 态（待处理/已处理）、**3 去向**（屏蔽数据/调整策略/补充数据）；推荐词保留 | 中 |
| P8 评测 | 评测集 + 标注 + 发起评测 + 报告 | **基准 + 重放对比**：评测列表、难例样本集（点踩自动汇总）、检查评测数据、对比视图、劣化判定 | 重写 |

## 2. 目标数据流与落库口径

新数据流里出现的四个逻辑对象，优先**复用现有表**，不照抄原型 sessionStorage 的命名：

| 逻辑对象 | 落库方案 | 说明 |
| --- | --- | --- |
| `cm_task_meta`（q/time/n/pair/user） | 扩展 `cmr_search_history` | 已有 query、结果数、任务号、时间；补操作人、模态对、策略快照、阈值、封存标记 |
| `cm_task_summary`（stg/thr/items[]） | `cmr_search_history` 存策略号/阈值 + `cmr_result_item` 存 Top-20 | 已有 rank/item_id/score；补 item_name、source、align_score（若 408 返回） |
| `cm_item_votes` | 新建 `cmr_item_vote` | 按“任务号 + 条目号”唯一，vote ∈ up/down；封存后只读 |
| `cm_blocked_items` | 新建 `cmr_blocked_item` | 结果运营屏蔽写这里；结果页渲染前排除并进“过滤清单” |
| `cm_blacklist`（数据源黑名单） | 新建 `cmr_datasource_blacklist` | 按来源名匹配整源排除；与条目屏蔽独立计数 |
| 收藏 | `cmr_favorite`（建议入库，按用户） | 原型为会话级；数据流 3.8 明确“只记条目 ID 与元数据、不复制文件”，入库不违背不出域 |

### 2.1 表变更清单

**新增（Liquibase 006–009）**

| 表 | 关键列 |
| --- | --- |
| `cmr_datasource_blacklist` | id、dataset_id、name、source_name、endpoint、create_id/time、del_flag |
| `cmr_item_vote` | id、task_no、item_id、vote(up/down)、user_id、create_time；唯一键 (task_no,item_id,user_id) |
| `cmr_blocked_item` | id、item_id、item_name、source、reason、feedback_id、create_id/time、del_flag |
| `cmr_favorite` | id、user_id、item_id、item_name、source、task_no、create_time；唯一键 (user_id,item_id) |
| `cmr_evaluation` | id、query、base_task_no、base_time、base_n、base_down、status、create_*；query 唯一 |

**扩展**

| 表 | 新增列 |
| --- | --- |
| `cmr_search_history` | operator_id、operator_name、query_modality、target_modality、strategy_no、strategy_version、threshold、sealed(char1)、replay_of_task_no、eval_id、summary_expire_time |
| `cmr_result_item` | item_name、source、align_score、item_modality（已有 modality 则复用） |
| `cmr_feedback` | entry_type(mismatch/zero)、source_task_no、source_query、mismatch_items(json)、judgment、disposition(block/strategy/supplement)、blocked(char1) |
| `cmr_strategy` | preset(char1)、offline_reason、offline_time、threshold(decimal) |
| `cmr_datasource` | required_ok(char1)、vectorized_count、total_count、last_sync_time、connect_status |

**停用（保留表，停止写入，接口下线）**

`cmr_eval_set`、`cmr_eval_item`、`cmr_eval_record`（评测改由 `cmr_evaluation` + 检索流水推导）；`cmr_click_event` 保留（点击埋点仍可用，但不再作为 P9 展示口径）。

**迁移口径**

- `cmr_feedback` 老数据：`processing` 归并到 `pending`，`closed` 保持；旧 4 类 type 映射到 `mismatch`（不匹配类）与 `zero`（零结果类），映射表写入 changelog 注释。
- `cmr_search_history` 补 `sealed='T'`：历史记录默认视为已封存，避免上线后旧任务被重新评价。
- `cmr_result_item` 的 `item_name/source` 回填脚本可空，读时按 item_id 回查（与 05 号文档口径一致）。

## 3. 接口改造

### 3.1 新增

| 方法 | 路径 | 用途 | 权限码 |
| --- | --- | --- | --- |
| POST | `/datasources/{id}/sync` | 手动同步：拉取 + 向量化，返回 taskNo、进度 | `cmr:dataset:create` |
| GET/POST | `/datasource-blacklist` | 黑名单分页/新增 | `cmr:dataset:page` / `cmr:dataset:create` |
| DELETE | `/datasource-blacklist/{id}` | 移出黑名单 | `cmr:dataset:update` |
| GET | `/search-behaviors` | 搜索行为分页：query/任务号/操作人/模态对/时间/有无踩/结果数 | `cmr:search:page` |
| GET | `/search-behaviors/{taskNo}` | 单条流水 + 赞踩汇总 | `cmr:search:page` |
| POST | `/search-behaviors/{taskNo}/rerun` | 重新执行：继承操作人/模态对/输入，生成新任务号 | `cmr:search:create` |
| GET | `/search-summary/{taskNo}` | 结果摘要：任务信息 8 项 + Top-20 | `cmr:search:page` |
| POST | `/search-summary/{taskNo}/mismatch` | 勾选不匹配条目 → 生成反馈单 | `cmr:feedback:create` |
| POST | `/search/results/{resultSetId}/vote` | 单条赞/踩：`{itemId, vote}`；封存后 409 | `cmr:search:create` |
| POST | `/search/results/{resultSetId}/seal` | 封存本次运行 | `cmr:search:create` |
| GET/POST/DELETE | `/favorites` | 收藏列表/切换/删除 | 登录即可 |
| GET | `/evaluations` | 评测列表：query、基准、重放次数、最新、结论 | `cmr:eval:page` |
| POST | `/evaluations` | 以一条搜索记录为基准（同 query 幂等） | `cmr:eval:create` |
| GET | `/evaluations/{id}/comparison` | 基准 + 最近 3 次重放指标对比 | `cmr:eval:detail` |
| GET | `/evaluations/hard-cases` | 难例样本集（点踩条目按 query 汇总） | `cmr:eval:page` |
| GET | `/evaluations/check-data` | 检查评测数据 4 项只读 | `cmr:eval:page` |

### 3.2 改造

| 接口 | 变化 |
| --- | --- |
| `POST /search` | 入参由 `scene` 改为 `strategyId`（可空→系统默认）；出参补 taskNo、resultSetId、strategyNo/version、threshold、items[].source/alignScore；写 `cmr_search_history` 时落操作人与模态对 |
| `GET /search/results/{resultSetId}` | 补 votes、favorite、sealed、excluded[]（黑名单/屏蔽命中明细）；移除 adoptStatus 语义 |
| `GET /search-history*` | 由 `/search-behaviors*` 替代；保留一个版本的重定向实现 |
| `POST /feedbacks` | 入参补 entryType、sourceTaskNo、mismatchItems[]；`description` 可空 |
| `POST /feedbacks/{id}/process` | 入参改为 `{judgment, disposition}`；一次完成待处理→已处理（去掉“处理中”中间态） |
| `POST /strategies/{id}/offline` `/online` | 新增；下线必填原因（四选一），系统预置拦截 |
| `GET /strategies/{id}/consistency` | 改为 5 项（可选策略≥1、默认兜底生效、阈值 0.30–0.99、权重合计 100%、已下线数量） |
| `GET /datasources` | 返回测试结果（状态/HTTP/耗时/时间）、字段完备、向量化计数、上次同步 |
| `POST /datasources/{id}/test` | 按 4 项必填（dataset_id/name/item_count/modals）逐项返回；缺项不改状态 |

### 3.3 下线（前端不再调用，接口保留一版后删除）

`POST /search/results/{id}/adopt`、`/discard`、`POST /file/package`（导出边界 3.8）、`/eval-sets/**`、`/eval-runs/**`、`POST /datasets/{id}/adjudicate`、`/confirm-production`、`POST /indexes/{id}/activate`、`GET /datasets/**`（前端不再展示）。

## 4. 分批实施

### 第一批：契约与骨架（1–2 天）

1. 更新 `docs/前后端规范/02-库表设计.md`、`03-API契约.md`：按本文第 2、3 节改表与接口，路由表变 6 菜单。
2. Liquibase `006_cmr_datasource_sync.xml`、`007_cmr_vote_favorite.xml`、`008_cmr_blocked_blacklist.xml`、`009_cmr_evaluation.xml`，含幂等 preConditions 与迁移 SQL。
3. `cmr-web/src/api/types.ts` / `index.ts` 补新类型与函数；后端补 entity/mapper/PO。
4. 路由与菜单：改为 6 项；`/history` → `/behaviors` 重定向；`/tasks/:id` 保留为失败任务详情（隐藏）。
5. 权限码补齐：`cmr:search:page`、`cmr:eval:*` 与菜单 `permissions` 三处一致。

### 第二批：三个重写页 + P4（3–5 天）

1. **P4 数据源库管理**（重写 `LibraryView.vue`）：数据源列表 7 列 + 对接弹窗 + 测试连接 4 项探测 + 同步 + 黑名单抽屉 + 接口对接定义只读面板。删除数据集列表、裁决、投产、索引激活的前端入口。
2. **P6 搜索行为**（新 `BehaviorView.vue`，替换 `TaskManageView.vue`）：流水表 + 详情/重新执行 + 失败任务表；操作人从登录态取。
3. **P3 搜索结果摘要**（重写 `TaskDetailView.vue` → `SearchSummaryView.vue`）：任务信息 8 项 + Top-20 表 + 勾选提交 + 已提交封存 + 无摘要空态；重放时顶部“当时 → 现在”。
4. **P1 检索台**：去掉业务场景，改检索策略下拉（只列生效中）+ 参数摘要；`strategyId` 随检索落库。

### 第三批：结果页评价闭环（3–4 天）

1. 结果卡：赞/踩（同向取消、反向改向）、收藏、封存态置灰、对齐分与来源。
2. 过滤：数据源黑名单（按来源名）+ 条目屏蔽，合并为“本次共排除 N 条”，只读过滤清单。
3. 零结果：原因分析、三条处置（放宽/换 query/登记需求），登记后进 P7。
4. 移除采用/废弃、批量下载、导出入口（对齐 3.8 数据不出域）。
5. 后端：vote/seal/favorite/blacklist 过滤统一在结果集读取时完成，避免前端各自过滤。

### 第四批：运营与评测（4–6 天）

1. **P7**：反馈单改 2 类型/2 态/3 去向；屏蔽数据写 `cmr_blocked_item` 并即时生效；调整策略/补充数据只记去向与处理判断；推荐词保留。
2. **P8**：评测列表（Query/基准/重放/最新/结论）、发起评测（选一条搜索记录定基准）、难例样本集、检查评测数据、对比视图（基准 + 最近 3 次重放 + 变化）、劣化判定（踩数上升 / 踩率 +5% / 结果数 −10%）。
3. 重放归集：`/search-behaviors/{taskNo}/rerun` 生成新任务，按 query 自动挂到评测；重放次数只增不减。
4. `EvalController` 的旧评测集/评测运行接口下线。

### 第五批：清理与验收（1–2 天）

1. 删除 `SearchHistoryView.vue`；`TaskManageView.vue`、`TaskDetailView.vue` 删除或改为仅失败任务。
2. 下线旧接口、旧字典（反馈类型/状态、场景字典在 P1 的用法）、旧种子数据。
3. 按第 5 节做正/负向用例，更新按钮清单文档状态。

## 5. 验收口径（直接取数据流的“不允许”）

| 页面 | 负向用例 |
| --- | --- |
| P4 | 4 项缺一仍转已连接；未连接数据源进入检索范围；黑名单来源仍被返回 |
| P1/P2 | 封存后改评价方向；封存后回到未评价；一条评价同时既赞又踩；小于 4 字未澄清就检索；文件检索触发澄清 |
| P3 | 已提交可回退未提交；同一任务生成两张不匹配反馈单；无摘要时复用其他任务摘要 |
| P5 | 系统默认策略可下线；草稿未发布变生效中；已下线直接回检索台下拉；同一策略两条生效版本 |
| P7 | 已处理回到待处理；重复处理；处理时改类型或手改去向；未处理预填去向 |
| P8 | 无重放却给出正常/已劣化；同 query 两条评测；已劣化不重放直接改正常 |
| 全局 | 任何下载/导出入口；结果页存文件本体；摘要超过 30 天仍可看明细 |

## 6. 风险与影响

1. **建库链**：新原型取消评定/裁决/投产，但 401–406 算子仍要跑。建议保留内部流水线，由“同步”触发，前端只暴露同步与向量化计数；`cmr_dataset` 保留为内部对象，不再作为页面主体。否则算子交付与本仓库会脱节。
2. **408 返回字段**：赞踩/摘要/对齐分依赖 408 出参；若当前算子不返回 `source/align_score`，P2 先做前端降级（来源留空、对齐分隐藏），不阻塞页面改造。
3. **老数据**：反馈状态归并与历史记录默认封存必须在 changelog 中显式写，避免上线后旧单无法处理。
4. **评测口径变化**：旧评测集/标注数据不再产生新结论，需在文档标注“历史归档”，避免测试按旧口径验收。
5. **权限**：P6/P7 原型有“管理员/只读”切换；本仓库鉴权此前临时下线，改造时按权限码禁用操作，不要恢复演示切换按钮。

## 7. 待确认（建议值）

1. **P9 检索历史**：建议并入 P6，`/history` 重定向；若仍要独立页，需在导航加回第 7 项，与 8 页口径冲突。
2. **收藏**：建议入库按用户持久化（`cmr_favorite`）；原型为会话级，若要严格照原型则只做前端 session。
3. **建库评审**：建议保留内部流水线、下线前端与评审接口；若确定不再跑 401–406，则 P4 同步只做“拉取 + 向量化”的最小链路，需同步算法侧。
4. **评测重放入口**：建议复用搜索行为的“重新执行”，按 query 自动归集；不新增独立“发起重放”按钮。
5. **任务详情**：建议只保留失败任务详情（`/tasks/:id`），检索任务的详情统一走搜索结果摘要。
