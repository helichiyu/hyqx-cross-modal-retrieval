# 跨模态检索中心 · 前后端对接说明

> 读者：本项目的前端、后端开发同学（2026-11-03 起前后端同为我方团队开发）。
> 算法侧交付：算子服务（单容器、9 个算子、仅 6300 端口）。本文说明各层调哪些接口、怎么调；字段级定义见《算子说明书》，可执行样例见《接口调用示例》。

## 一、整体架构与调用链

```
浏览器 ──HTTP──▶ Java 后端（/hs-api/cmr/...） ──HTTP──▶ 算子服务（内网 :6300）
  │                     │
  └─ 静态资源 ◀── nginx │ 共享数据卷：dataset/ 与 runtime/（后端与算子容器同名挂载）
```

**铁律**：

1. **浏览器不直连 6300**——算子服务只允许后端内网访问。检索历史（SRH）、任务记录均由后端落库，必须经后端中转。
2. 前端只调 Java 后端的 REST API（`/hs-api/cmr/...`），契约见《前后端总体技术方案》。
3. 后端与算子容器**同名挂载 dataset、runtime 两个目录**：算子返回的 `runtime/...`、`dataset/...` 逻辑路径，后端拼共享卷根即可直接读文件（媒体预览、材料下载），无需算子提供文件下载接口。

## 二、各层拿到的东西

- 算子镜像：进入 `operators/` 后 `docker compose up -d --build` 一条命令起服务（交付根即 `operators/`）。
- 服务地址：`http://<host>:6300`，HTTP + JSON，统一信封 `{"code": 0, "msg": "success", "data": {...}}`；`code=1` 为业务失败，`msg` 带原因，HTTP 层仍为 200（仅参数格式错才回 4xx）。
- 健康检查：`GET /healthz`（全部算子聚合）、`GET /{算子编号}/healthz`（单个算子）。

## 三、职责分层

| 层 | 职责 |
| --- | --- |
| 算子服务（已交付） | 9 个算子：校验/评定/解析/向量化/建索引/召回校验/查询理解/检索/评测；向量模型与索引结构 |
| Java 后端 | 数据集管理、建库链编排与状态机、检索编排与历史落库、策略存储与版本、评测记录、反馈与推荐词、文件服务、用户权限 |
| 前端 | 9 个页面（P1–P9）+ 门户与登录 |

## 四、三条链路，谁调什么

```
建库链（后端编排，异步批量任务）      在线链（后端代理，同步低延迟）      评测链（后端触发，异步）
401 校验 → 402 评定 → 判定pass?     407 查询理解 →（需澄清则交互）    409 评测执行
   ↓ 是                             408 /search 检索 → 结果集RST      （对比上次、达标结论）
403 解析 → 404 向量化 → 405 建索引
   ↓
406 投产召回校验 → pass 才切索引
```

- **在线链由后端代理**：前端把查询交给后端，后端先调 `407m_query_understand/predict`，`needClarify=true` 时把澄清选项返给前端交互；用户选定后后端拿选项里的 `query` 调 `408m_retrieval/search`，结果集落库（SRH）后返回前端。
- **建库链与评测链**：后端包成异步任务（链路串行、分钟级），`408` 也可被后端调用（数据预览、相似文件查找）。

## 五、路径约定（重要）

- 算子侧所有输入/输出路径支持两种写法：**项目根相对逻辑路径**（`runtime/...`、`dataset/...`，推荐）与绝对路径。
- 算子产出（items/报告/检索结果）里的 `sourceFile`、`locator.path` 一律为逻辑路径。
- 后端读文件 = 共享卷根 + 逻辑路径（`dataset` 卷配 `dataset/...`，`runtime` 卷配 `runtime/...`）。
- `uniqueId`：每次任务全局唯一（字母数字下划线短横线，≤128），建议 `{业务前缀}_{日期}_{序号}`；同一 uniqueId 的上传/输出目录复用，重跑即覆盖。
- 上传：`POST /{算子}/uploadFile?uniqueId=...`（multipart），落在 `runtime/{算子}/input/{uniqueId}/`，zip 自动解压；后端也可直接把文件写入共享卷 dataset 区后以路径传参（免转传）。
- 清理：`POST /{算子}/removeFile?uniqueId=...`，幂等可重试。

## 六、在线链细节

### 407 查询理解（可选前置，建议都走）

查询提交后先调它，`data.needClarify=true` 时弹澄清交互：

- `clarifyOptions`：数组，每项 `intent`（意图说明）、`query`（改写后查询）、`hint`（提示词）。
- 用户选定后，**用选项里的 `query`** 调 408（不是原始输入）。
- `needClarify=false`：直接用原始查询调 408。

### 408 检索（主接口 `POST /408m_retrieval/search`）

请求字段（均可选，除查询本身）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| query / queryFile | string | 二选一；queryFile 为图片/音频/视频逻辑路径（以图搜图、以音搜音） |
| indexDir | string | 索引目录（`runtime/xxx`）；不传用服务端当前激活索引 |
| topK | int | 返回条数，默认 20 |
| weights | object | 四模态权重 `{text,image,audio,video}`，**合计必须 100**，否则 code=1 |
| rerank | bool | 精排开关，默认关；开则更准但更慢（约 +1.3 s） |

响应 `data` 关键字段：

| 字段 | 用途 |
| --- | --- |
| resultSetId | 结果集编号（RST 前缀）；后端存检索历史时带上它 |
| items[] | rank/score/modality/itemId/sourceFile/locator/text，按相似度降序 |
| modality | text / image / audio / video，前端按模态出图标或分栏 |
| sourceFile + locator | 命中位置回溯：文本是段序号、音频是起止秒、视频是帧时间点；**均为逻辑路径，后端加共享卷根即可取媒体内容给前端预览** |
| strategy | 本次策略快照（权重/重排/topK） |
| elapsedMs | 服务端耗时 |

策略生效方式：后端把当前生效策略的 weights/rerank 随每次检索请求携带即可，**改完下一次请求即生效**（服务端无状态）。

## 七、建库链细节

### 编排顺序

严格串行，每环的 `data.outputFile` 作为下一环的 `inputFile`：

```
401 校验（inputFile=数据集目录） → report.json
402 评定（inputFile=report.json） → decision=pass 才继续；suspend 人工裁决；reject 终止
403 解析（inputFile=数据集目录）   → items.jsonl
404 向量化（inputFile=items.jsonl） → embeddings.jsonl
405 建索引（inputFile=embeddings.jsonl, itemsFile=items.jsonl, indexDir=runtime/index/新目录） → counts
406 投产校验（indexDir, evalFile） → decision=pass 才把该 indexDir 设为激活索引
```

### 超时与任务化

- predict 是**同步长调用**：小数据集秒级，403 视频抽帧、404 批量编码在大数据集上是分钟级。
- 后端把整条链包成异步任务（任务表 + 状态机），调算子的 HTTP 客户端超时 ≥ 30 分钟；我方接口无轮询语义，一次调用返回全部结果。
- 408 在线检索毫秒~秒级（关精排 <1 s，开精排约 2 s，CPU 环境），后端代理超时 10 s。

### 判定字段对接

| 算子 | 字段 | 语义 |
| --- | --- | --- |
| 402 | `decision` | pass / suspend / reject，suspend 走人工裁决流 |
| 406 | `decision` | pass / fail，fail 不投产（线值 threshold 可传参覆盖） |
| 409 | `conclusion` / `failedLines` | pass / fail 与未达标指标清单 |
| 409 | `comparison` | 与同索引上次评测的差值，`improved` 可直接做"较上次提升"标记 |

### 评测对象=策略（409）

`409m_evaluate/predict` 接受 `weights`/`rerank`（可省略）：传候选草稿策略即可对比"草稿 vs 生效"，指标差值供发布决策。

### 索引目录管理

- 每次建库传**新** indexDir（如 `runtime/index/20261104_001`），406 通过后切换激活索引（改 `operators/config.yaml` 的 `retrieval.active_index` 或检索请求带 indexDir），老索引保留供回滚。
- 换向量模型（modelVersion 变化）后旧索引自动失效，需整链重建——算法侧约束，后端不用处理兼容。

## 八、部署与环境

三条命令（详见《部署说明》）：

```
docker compose up -d --build
```

```
curl http://127.0.0.1:6300/healthz
```
