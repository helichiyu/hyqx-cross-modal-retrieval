# 跨模态检索中心 · 算子服务部署说明

> 交付物：9 个算子，单容器单端口（6300），路由层统一暴露四协议。
> 适用环境：Linux（容器）为主，Windows 本机运行兼容。

## 一、交付物清单

| # | 产物 | 位置 |
| --- | --- | --- |
| 1 | 算子源码（9 算子 + 统一路由层 + config.yaml + map.json） | `operators/`（自包含交付根） |
| 2 | Dockerfile（python:3.12-slim，EXPOSE 6300，含健康检查） | `operators/Dockerfile` |
| 3 | 算子说明书（每算子一份，docx + md 双格式） | `docs/算子说明书/` |
| 4 | 每算子 README（接口速查） | `operators/*/README.md` |
| 5 | 部署说明（本文） | `docs/部署说明.md` |
| 6 | 接口调用示例（建库链 + 在线检索全流程可执行样例） | `docs/接口调用示例.md` |
| 7 | 测试数据（样例四模态数据集 + 评测集） | `dataset/sample/`、`dataset/sample.zip` |
| 8 | 测试指令（端到端脚本 e2e_m1/m2/m3 + 协议测试） | `scripts/`、`tests/` |
| 9 | 前后端对接说明（分工与调用指引） | `docs/前后端对接说明.md` |
| 10 | 交付包（仅 Docker 构建所需内容，`python scripts/make_package.py` 生成） | `dist/cmr-operators.zip` |

## 二、模型权重清单

| 模型 | 用途 | 下载目录 | 大小 | 来源 |
| --- | --- | --- | --- | --- |
| chinese-clip-vit-base-patch16 | 文本/图片/视频帧向量化（512 维） | `{model_root}/chinese-clip-vit-base-patch16` | 约 1.4 GB | ModelScope 或 HF 镜像 |
| clap-htsat-fused | 音频向量化与音频文本塔（512 维） | `{model_root}/clap-htsat-fused` | 约 1.2 GB | 同上 |
| bge-reranker-v2-m3 | 检索精排（可选开启） | `{model_root}/bge-reranker-v2-m3` | 约 2.2 GB | 同上 |

- `model_root` 在 `operators/config.yaml` 的 `paths.model_root` 配置，容器内默认 `/weight`。
- 下载脚本：`python scripts/download_models.py`（ModelScope 优先，hf-mirror 兜底）。
- 三个模型目录均须含 `config.json`；缺失时对应算子 healthz 报 degraded，服务不启动失败。

## 三、资源要求

| 资源 | 最低 | 建议 |
| --- | --- | --- |
| CPU | 4 核 | 8 核（视频抽帧与 CPU 推理受益） |
| GPU | 无（CPU 可全量运行） | 可选；提供 GPU 时 torch 自动加速批量编码与精排 |
| 内存 | 8 GB | 16 GB（三模型全加载约 5 GB） |
| 磁盘 | 模型 4.8 GB + 数据集 2 倍空间 | SSD |

## 四、Docker 部署（推荐 compose）

1. 解压交付包 `dist/cmr-operators.zip`，进入目录。
2. 权重放到 `./weight` 下（按第二节清单，三个模型子目录）。
3. 一条命令构建并启动：

```
docker compose up -d --build
```

- 端口映射 `6300:6300`；权重挂载 `./weight:/weight`；任务与索引持久化 `./runtime:/app/runtime`。
- 容器经环境变量 `CMR_MODEL_ROOT=/weight` 覆盖 `operators/config.yaml` 的 `paths.model_root`，**无需改配置文件**；同理可用 `CMR_RUNTIME_ROOT`、`CMR_DATASET_ROOT` 覆盖另两个路径。
- 健康检查：容器内置每 30 秒探活 `/healthz`。
4. 验证：`curl http://127.0.0.1:6300/healthz`，返回 `code=0` 且 `operators` 列出 9 个算子。

不用 compose 的等效命令：

```
docker run -d --name cmr-operators -p 6300:6300 -e CMR_MODEL_ROOT=/weight -v /data/models:/weight -v /data/cmr-runtime:/app/runtime cmr-operators:1.0
```

## 五、本机直跑（不建容器）

1. Python 3.12 环境，安装依赖：`pip install -r operators/requirements.txt`（在仓库根目录执行）。
2. 修改 `operators/config.yaml` 的 `paths.model_root` 指向本机权重目录。
3. 启动（在仓库根目录执行）：`python -m uvicorn operators.router.main:app --host 0.0.0.0 --port 6300`

## 六、配置项说明（改配置不改代码）

`operators/config.yaml` 关键项：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| server.port | 6300 | 对外唯一端口 |
| paths.model_root | D:/models（本机）/weight（容器） | 权重根目录 |
| paths.runtime_root | ./runtime | 任务输入输出与索引根目录 |
| models.model_version | cmr-embed-v1 | 向量模型版本号；换向量模型必须改此值并重建索引 |
| retrieval.active_index | runtime/demo_index | 在线检索默认索引目录 |
| retrieval.top_k | 20 | 默认返回条数 |
| retrieval.weights | text 25 / image 25 / audio 25 / video 25 | 默认融合权重，合计必须 100 |
| retrieval.rerank | false | 默认是否开启精排 |
| retrieval.rerank_top_n | 50 | 参与精排的候选条数 |
| retrieval.word_weight | 2.0 | 精确词命中加成系数 |

索引目录由 `retrieval.active_index` 或检索请求的 `indexDir` 参数指定，两者都支持相对 `runtime_root` 的路径。

## 七、启动自检清单

1. `GET /healthz` 返回 `code=0`，`operators` 含全部 9 个算子编号。
2. 任一算子 `GET /{operatorId}/healthz`，`status=ok`（权重缺失时 `degraded`，补权重后重启恢复）。
3. 建库链冒烟：按《接口调用示例》第一节跑通样例数据集。
4. 在线检索冒烟：按第二节跑通一次文本检索。
