# 算子模型设计

## 数据接入校验

### 数据接入校验

#### 文件魔数识别与可解码性校验规则

##### 基础信息

| 项 | 值 |
| --- | --- |
| 算子编号 | 401m_ingest_check |
| 算子名称 | 数据接入校验 |
| 算子类型 | 批量处理 |
| 接口路径 | /401m_ingest_check/predict |
| 输入 | 数据集目录（文本、图片、音频、视频四类文件） |
| 输出 | 校验报告 report.json、失败清单 failures.json、血缘文件 lineage.jsonl |
| 依赖模型 | 无 |

##### 技术方案

对待接入数据集逐文件执行两级校验。第一级为格式识别：读取文件头魔数判定真实格式，与扩展名声明的格式比对，二者不一致记为格式伪装。第二级为可解码性校验：图片用 Pillow 解码验证，音频与视频用 FFmpeg 试解码，文本按 UTF-8 读取验证。校验结果与数据集随附的 metadata.json 清单对账，统计实际文件数与清单声明数的一致率。算子只产出客观校验指标，不下通过与否的结论，结论由下游数据集评定算子给出。

##### 技术实现

1. 遍历输入目录，按扩展名归类文本、图片、音频、视频四类文件
2. 读取每个文件头部字节，按魔数表识别真实格式，与扩展名比对
3. 对图片执行解码验证，对音频视频执行试解码，对文本执行 UTF-8 读取验证
4. 读取 metadata.json，对账文件数量与各模态覆盖率
5. 汇总可解码率、模态覆盖率、数量一致率三项指标写入 report.json
6. 将未通过校验的文件及原因写入 failures.json
7. 逐文件追加血缘记录到 lineage.jsonl

##### 资源要求

| 资源 | 要求 |
| --- | --- |
| CPU | 2 核及以上 |
| GPU | 不需要 |
| 内存 | 2 GB 及以上 |
| 磁盘 | 与待校验数据集等量空间用于上传暂存 |

##### 模型性能指标

本算子不含训练模型。在样例数据集（文本 1 个、图片 1 张、65 秒音频 1 段、6 秒视频 1 段）上实测，单轮全量校验耗时约 0.5 秒，三项指标准确率与人工核对一致。

##### 数据接入校验-输入示例

请求：

```
POST /401m_ingest_check/predict
{
  "uniqueId": "task_001",
  "inputFile": "runtime/401m_ingest_check/input/task_001"
}
```

输入目录由 /uploadFile 接口上传，支持 zip 自动解压，目录内为待校验的数据集文件。

##### 数据接入校验-输出示例

```
{
  "code": 0,
  "msg": "success",
  "data": {
    "outputFile": "runtime/401m_ingest_check/output/task_001/report.json",
    "report": {
      "totalFiles": 4,
      "decodableRate": 1.0,
      "modalityCoverage": 1.0,
      "countRate": 1.0,
      "byModality": {"text": 1, "image": 1, "audio": 1, "video": 1}
    },
    "failureCount": 0
  }
}
```

report.json 内 datasetDir、failures 清单与 lineage.jsonl 的 sourceFile 均为**项目根相对逻辑路径**（runtime/... 或 dataset/...），调用方按同名目录挂载即可定位原始文件。
