# 算子模型设计

## 向量索引构建

### 向量索引构建

#### FAISS 内积索引与 SQLite 元数据双通道存储

##### 基础信息

| 项 | 值 |
| --- | --- |
| 算子编号 | 405m_index_build |
| 算子名称 | 向量索引构建 |
| 算子类型 | 批量处理 |
| 接口路径 | /405m_index_build/predict |
| 输入 | embeddings.jsonl，可选 items.jsonl 与 indexDir |
| 输出 | 索引目录（index_clip.faiss、index_clap.faiss、meta.db、index_meta.json） |
| 依赖模型 | 无（索引结构使用 FAISS IndexFlatIP） |

##### 技术方案

按向量通道分建两个 FAISS 索引文件。文本、图片、视频帧单元进入 clip 通道，音频单元进入 clap 通道，均使用内积精确检索结构 IndexFlatIP，配合 IndexIDMap2 以元数据行号作为向量标识。单元元数据（itemId、模态、来源文件、定位信息、文本内容）存入索引目录下的 SQLite 库 meta.db。索引目录附带 index_meta.json 记录模型版本号，向量模型更换后旧索引自动判定失效，防止跨版本混用。同一索引重复构建时，模型版本不一致会被拒绝。

##### 技术实现

1. 读取 embeddings.jsonl 与 items.jsonl，按 itemId 对齐向量与元数据
2. 校验向量模型版本与已有索引版本一致，不一致则拒绝构建
3. 按通道将向量写入对应 FAISS 索引，向量标识为元数据行号
4. 将元数据写入 meta.db 的 items 表
5. 将模型版本与统计信息写入 index_meta.json

##### 资源要求

| 资源 | 要求 |
| --- | --- |
| CPU | 2 核及以上 |
| GPU | 不需要 |
| 内存 | 2 GB 及以上；百万级向量规模按每百万条约 2 GB 内存预留 |
| 磁盘 | 每百万条 512 维向量约 2 GB（单通道） |

##### 模型性能指标

本算子不含训练模型。在样例数据集 12 个检索单元上实测，单轮建库耗时约 0.4 秒。IndexFlatIP 为精确检索，召回结果与暴力枚举一致。

##### 向量索引构建-输入示例

```
POST /405m_index_build/predict
{
  "uniqueId": "task_001",
  "inputFile": "runtime/404m_embed/output/task_001/embeddings.jsonl",
  "itemsFile": "runtime/403m_modal_parse/output/task_001/items.jsonl",
  "indexDir": "runtime/demo_index"
}
```

itemsFile 与 indexDir 可省略；indexDir 省略时写入默认索引目录。

##### 向量索引构建-输出示例

```
{
  "code": 0,
  "msg": "success",
  "data": {
    "indexDir": "runtime/demo_index",
    "counts": {"text": 2, "image": 1, "audio": 3, "video": 6},
    "total": 12,
    "modelVersion": "cmr-embed-v1"
  }
}
```
