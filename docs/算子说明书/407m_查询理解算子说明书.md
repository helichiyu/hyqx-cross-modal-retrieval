# 算子模型设计

## 查询理解

### 查询理解

#### 歧义词典与查询模态识别规则

##### 基础信息

| 项 | 值 |
| --- | --- |
| 算子编号 | 407m_query_understand |
| 算子名称 | 查询理解 |
| 算子类型 | 在线服务 |
| 接口路径 | /407m_query_understand/predict |
| 输入 | 查询文本 query，或查询文件路径 queryFile |
| 输出 | 澄清标记、澄清选项、查询模态 |
| 依赖模型 | 无（歧义词典 configs/ambiguity.json） |

##### 技术方案

对用户查询做两种前置判断。第一种是歧义消解：查询命中歧义词典时返回澄清选项，每个选项给出意图说明与改写后的查询，由前端展示给用户选择。第二种是完备性检查：查询长度不足 3 个字符时返回补充提示，不进入检索。输入为查询文件时按扩展名识别查询模态，文本、图片、音频、视频各归其类。歧义词典外置于配置文件，可在不改动代码的情况下扩充词条。

##### 技术实现

1. 接收查询文本或查询文件路径，二者必须提供其一
2. 查询文本先查歧义词典，命中则生成澄清选项列表并置澄清标记
3. 未命中歧义词典且长度不足 3 个字符时，返回补充描述提示并置澄清标记
4. 查询文件按扩展名映射到文本、图片、音频、视频四类模态
5. 正常查询返回澄清标记为否及识别出的查询模态

##### 资源要求

| 资源 | 要求 |
| --- | --- |
| CPU | 1 核及以上 |
| GPU | 不需要 |
| 内存 | 512 MB 及以上 |
| 磁盘 | 歧义词典小于 1 MB |

##### 模型性能指标

本算子不含训练模型。单次查询理解耗时在 0.4 秒以内。样例验证覆盖正常查询、歧义命中、过短查询、文件模态识别四类分支。

##### 查询理解-输入示例

文本查询：

```
POST /407m_query_understand/predict
{
  "uniqueId": "q_001",
  "query": "苹果的照片"
}
```

文件查询：

```
POST /407m_query_understand/predict
{
  "uniqueId": "q_002",
  "queryFile": "runtime/407m_query_understand/input/q_002/dog.jpg"
}
```

##### 查询理解-输出示例

歧义命中时返回澄清选项：

```
{
  "code": 0,
  "msg": "success",
  "data": {
    "needClarify": true,
    "clarifyOptions": [
      {"intent": "苹果水果类", "query": "苹果水果照片", "hint": "水果"},
      {"intent": "苹果手机或苹果公司", "query": "苹果手机照片", "hint": "苹果手机或苹果公司"}
    ]
  }
}
```

正常查询：

```
{
  "code": 0,
  "msg": "success",
  "data": {
    "needClarify": false,
    "queryModality": "text"
  }
}
```
