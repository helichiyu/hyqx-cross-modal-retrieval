# 算子模型设计

## 模态内容解析

### 模态内容解析

#### 分模态切片与检索单元抽取规则

##### 基础信息

| 项 | 值 |
| --- | --- |
| 算子编号 | 403m_modal_parse |
| 算子名称 | 模态内容解析 |
| 算子类型 | 批量处理 |
| 接口路径 | /403m_modal_parse/predict |
| 输入 | 数据集目录（文本、图片、音频、视频四类文件） |
| 输出 | 检索单元清单 items.jsonl、血缘文件 lineage.jsonl |
| 依赖模型 | 无（音视频解码使用 FFmpeg） |

##### 技术方案

将四种模态的文件切成可独立检索的单元。文本按 500 字分段，相邻段重叠 50 字；图片一张为一个单元；音频按 30 秒切片，转为 48 kHz 单声道 WAV；视频按每秒 1 帧抽帧，一帧为一个单元。每个单元分配唯一 itemId，并记录其来源文件与定位信息（文本为段序号，音频为起止秒，视频为帧时间点），供检索结果回溯到原文位置。

##### 技术实现

1. 遍历输入目录，按扩展名识别四种模态文件
2. 文本文件按 500 字分段、50 字重叠生成单元，text 字段保存段内容
3. 图片文件每张生成一个单元
4. 音频文件经 FFmpeg 转码后按 30 秒切片生成单元，locator 记录起止秒
5. 视频文件按每秒 1 帧抽帧生成单元，locator 记录帧时间点
6. 全部单元写入 items.jsonl，每行一个单元
7. 逐文件追加血缘记录到 lineage.jsonl

##### 资源要求

| 资源 | 要求 |
| --- | --- |
| CPU | 4 核及以上（视频抽帧为计算密集操作） |
| GPU | 不需要 |
| 内存 | 4 GB 及以上 |
| 磁盘 | 音频切片与视频抽帧会产生中间文件，预留数据集两倍空间 |

##### 模型性能指标

本算子不含训练模型。在样例数据集（文本 1 个、图片 1 张、65 秒音频 1 段、6 秒视频 1 段）上实测，单轮解析耗时约 0.5 秒，产出检索单元 12 个，四种模态全覆盖。

##### 模态内容解析-输入示例

```
POST /403m_modal_parse/predict
{
  "uniqueId": "task_001",
  "inputFile": "runtime/401m_ingest_check/input/task_001"
}
```

##### 模态内容解析-输出示例

```
{
  "code": 0,
  "msg": "success",
  "data": {
    "outputFile": "runtime/403m_modal_parse/output/task_001/items.jsonl",
    "counts": {"text": 2, "image": 1, "audio": 3, "video": 6},
    "itemCount": 12
  }
}
```

items.jsonl 每行结构：

```
{"itemId": "txt_000001", "sourceFile": "dataset/sample/notes.txt", "modality": "text", "text": "……", "locator": {"segment": 0, "charStart": 0}}
{"itemId": "aud_000003", "sourceFile": "dataset/sample/podcast.wav", "modality": "audio", "locator": {"path": "runtime/403m_modal_parse/output/task_001/podcast_slices/slice_0001.wav", "startSec": 30, "endSec": 60}}
```

sourceFile 与 locator.path 均为**项目根相对逻辑路径**（runtime/... 或 dataset/...）：上传产物位于 runtime，随数据集入库的原始文件位于 dataset。调用方按同名目录挂载即可直接读取媒体内容，不感知算子容器内部绝对路径；下发 inputFile、queryFile 时同样使用该写法（也接受绝对路径）。
