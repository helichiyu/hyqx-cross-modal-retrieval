# 算子模型设计

## 检索服务

### 检索服务

#### 双通道召回与加权融合检索模型

##### 基础信息

| 项 | 值 |
| --- | --- |
| 算子编号 | 408m_retrieval |
| 算子名称 | 检索服务 |
| 算子类型 | 在线服务 |
| 接口路径 | /408m_retrieval/search（四协议 /predict 同逻辑） |
| 输入 | 查询文本或查询文件，索引目录 indexDir |
| 输出 | 结果集 RST（resultSetId、条目列表、策略、耗时） |
| 依赖模型 | Chinese-CLIP ViT-B/16、CLAP HTSAT（经多模态向量化算子调用）；bge-reranker-v2-m3（精排，可选） |

##### 技术方案

在线检索按查询模态确定召回通道。文本查询同时在 clip 通道（文本、图片、视频帧）与 clap 通道（音频）召回；图片与视频查询走 clip 通道；音频查询走 clap 通道。各通道召回量为目标条数的五倍，通道内得分做 z-score 归一后取非负部分，按四模态策略权重加权融合，权重合计必须为 100。融合阶段叠加精确词命中加成，按词覆盖率加成，用于检索发票号、错误码这类语义向量难以保住的精确词。开启精排时，含文本的候选条目由 bge-reranker-v2-m3 对查询与条目文本联合打分重排。结果按总分降序输出前 topK 条，并生成结果集编号。

##### 技术实现

1. 校验查询与索引目录，比对索引模型版本，版本不一致拒绝检索
2. 校验融合权重合计为 100
3. 按查询模态调用多模态向量化算子生成查询向量
4. 各通道 FAISS 召回目标条数五倍的候选，通道内 z-score 归一取非负
5. 同一条目多通道命中时保留 z 值最高者
6. 按模态权重加权求和，叠加精确词覆盖加成
7. 开启精排时对前 rerank_top_n 条含文本条目执行重排打分
8. 按总分降序截取 topK 条，生成结果集编号与策略快照返回

##### 资源要求

| 资源 | 要求 |
| --- | --- |
| CPU | 4 核及以上 |
| GPU | 不需要；配置 GPU 可显著缩短精排耗时 |
| 内存 | 8 GB 及以上（重排模型加载约 2.2 GB 磁盘、2 GB 内存） |
| 磁盘 | bge-reranker-v2-m3 权重约 2.2 GB |

##### 模型性能指标

在样例索引（12 个检索单元）上实测（CPU 环境）：关闭精排时服务端检索耗时约 0.7 秒；开启精排时约 2.0 秒。语义正确性经评测算子验证，样例评测集 recall@10 为 1.0。

##### 检索服务-输入示例

```
POST /408m_retrieval/search
{
  "query": "一只狗在沙滩上奔跑",
  "indexDir": "runtime/demo_index",
  "topK": 10,
  "weights": {"text": 25, "image": 25, "audio": 25, "video": 25},
  "rerank": false
}
```

topK、weights、rerank、indexDir 均可省略，省略时使用服务配置默认值。查询文件检索时传 queryFile 字段替代 query。

##### 检索服务-输出示例

```
{
  "code": 0,
  "msg": "success",
  "data": {
    "resultSetId": "RST20261103153000A1B2C3",
    "query": "一只狗在沙滩上奔跑",
    "queryModality": "text",
    "count": 10,
    "items": [
      {"rank": 1, "score": 0.528178, "modality": "image",
       "itemId": "img_000002", "sourceFile": "dog_beach.jpg"}
    ],
    "strategy": {"weights": {"text": 25, "image": 25, "audio": 25, "video": 25},
                 "rerank": false, "topK": 10},
    "modelVersion": "cmr-embed-v1",
    "elapsedMs": 727.5
  }
}
```

items 内每条含 rank、score、modality、itemId、sourceFile、locator、text；文本单元的 text 为分段内容，音视频单元的 locator 为切片或帧位置。sourceFile 与 locator.path 为**项目根相对逻辑路径**（runtime/... 或 dataset/...），调用方按同名目录挂载即可读取命中媒体内容用于展示；queryFile 下发同样使用该写法（也接受绝对路径）。
