# 算子模型设计

## 多模态向量化

### 多模态向量化

#### Chinese-CLIP 与 CLAP 双通道向量化模型

##### 基础信息

| 项 | 值 |
| --- | --- |
| 算子编号 | 404m_embed |
| 算子名称 | 多模态向量化 |
| 算子类型 | 批量处理与在线服务 |
| 接口路径 | /404m_embed/predict |
| 输入 | 批量模式为 items.jsonl；在线模式为查询文本或查询文件路径 |
| 输出 | 批量模式为 embeddings.jsonl；在线模式在响应中直接返回向量 |
| 依赖模型 | Chinese-CLIP ViT-B/16（文本、图片、视频帧通道）；CLAP HTSAT（音频通道及其文本塔） |

##### 技术方案

采用两个向量化模型构成两条通道。文本、图片、视频帧经 Chinese-CLIP ViT-B/16 编码为 512 维向量，该模型在中文语料上训练，文本与图像在同一向量空间对齐。音频经 CLAP HTSAT 编码为 512 维向量；文本查音频场景使用 CLAP 文本塔将查询文本编码到音频向量空间。全部向量做 L2 归一化，余弦相似度等价于内积。模型以懒加载单例驻留内存，首次调用时加载。

##### 技术实现

1. 批量模式读取 items.jsonl，按模态分组
2. 文本与图片及视频帧单元调用 Chinese-CLIP 编码，音频单元调用 CLAP 编码
3. 请求参数 channel 为 clap 时，文本经 CLAP 文本塔编码，用于文本查音频
4. 所有向量执行 L2 归一化
5. 批量模式将向量逐行写入 embeddings.jsonl，并记录模型版本号
6. 在线模式接收 queryText、queryImagePath、queryAudioPath 之一，在响应中返回向量

##### 资源要求

| 资源 | 要求 |
| --- | --- |
| CPU | 4 核及以上 |
| GPU | 不需要；配置 GPU 可缩短批量编码耗时 |
| 内存 | 8 GB 及以上（加载后内存占用约 3 GB） |
| 磁盘 | 模型权重约 2.6 GB（Chinese-CLIP 约 1.4 GB，CLAP 约 1.2 GB） |

##### 模型性能指标

Chinese-CLIP ViT-B/16 输出 512 维向量，CLAP HTSAT 输出 512 维向量。在样例数据集 12 个检索单元上实测，批量编码总耗时约 1.6 秒（CPU 环境）。在线模式单条文本查询编码耗时在 1 秒以内。

##### 多模态向量化-输入示例

批量模式：

```
POST /404m_embed/predict
{
  "uniqueId": "task_001",
  "inputFile": "runtime/403m_modal_parse/output/task_001/items.jsonl"
}
```

在线模式（文本查音频通道）：

```
POST /404m_embed/predict
{
  "uniqueId": "q_001",
  "queryText": "播客里讲睡眠",
  "channel": "clap"
}
```

##### 多模态向量化-输出示例

批量模式：

```
{
  "code": 0,
  "msg": "success",
  "data": {
    "outputFile": "runtime/404m_embed/output/task_001/embeddings.jsonl",
    "count": 12,
    "dim": 512,
    "modelVersion": "cmr-embed-v1"
  }
}
```

在线模式：

```
{
  "code": 0,
  "msg": "success",
  "data": {
    "dim": 512,
    "channel": "clap",
    "vector": [0.012, -0.034]
  }
}
```

vector 为 512 维浮点数组，上例仅截取前两位示意。
